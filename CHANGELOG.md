# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии по [SemVer](https://semver.org/lang/ru/).
Линия `0.x` рассчитана на **SolidJS 1.x** (`peerDependencies: solid-js ^1.8.0`).

## [Unreleased]

### Изменено
- `DumbSortableDnd` больше не трогает DOM при сортировке: элементы рендерятся в
  неизменном порядке, а показывает их браузер по CSS `order`. Контейнер обязан
  быть flex или grid.
- Отмена жеста по Escape ловится через `keyup`: во время нативного драга
  `keydown` до страницы не доходит вовсе.

## [0.4.0] — 2026-07-31

### Добавлено
- `DumbSortableDnd` — сортировка списка и сетки на **нативном** drag-and-drop (`createDumbSortableDnd`, движок `createSortDndEngine`). Место вставки не вычисляется: зона приёма висит на каждой строке, и `dragover` приходит ровно на ту, над которой указатель, — хиттест делает браузер. Данные до дропа не трогаются, меняется только порядок мест, а доигрывает его FLIP: едет и перетаскиваемая строка, и соседи между старым местом и новым; остальные не шевелятся, и в их `style` не попадает ни байта. Насколько двигать — арифметика по одному разовому замеру (`IntersectionObserver`, off-main-thread): соседи на высоту перетаскиваемой строки с зазором, сама строка на сумму высот тех, кого перешагнула, сетка на разницу мест. Везде разницы, а не абсолютные координаты, поэтому прокрутка — колесом, автоскроллом, чем угодно — на расчёт не влияет. Место живёт в координатах списка БЕЗ перетаскиваемой строки: через исходные индексы жест выходит несимметричным, и шаг назад съедается. Тач не поддерживается (HTML5 DnD там не существует) — для пальца остаётся `DumbSortable`.
- `createFlip` — проигрыватель FLIP-сдвигов на Web Animations. Элементу говорят, на сколько отъехать (`to`) либо что он уже переехал и переезд надо доиграть (`nudge`), — дальше он едет `transform`ом на композиторе. Не `style.transition`: переход, назначенный в одном кадре с трансформом, не запускается, и обойти это можно только развесив переходы заранее всем элементам списка — сотни записей в `style` ради трёх реально едущих. `el.animate()` стартует сразу и в `style` не пишет вовсе. Анимацию, перебитую на полпути, подхватывает с той точки, где она находится: положение считается обращением кривой Безье, layout не читается.
- `createAutoScroller` — автопрокрутка во время перетаскивания, общая для DnD-фич кита. В кадре не читается ничего: положение прокрутки движок ведёт сам, а расхождение (крутят колесом снаружи) ловит пассивным слушателем `scroll`. Цикл засыпает, как только крутить нечего, и просыпается на движении. Координаты курсора берутся из нативного `drag` — он приходит и при неподвижной мыши, когда `dragover` уже молчит, а прокрутка нужна как раз у самого края. Готовая из Pragmatic не подошла: она крутит, только пока курсор над зарегистрированной целью, а за нижним краем списка целей нет вовсе.

- `DumbGrid` — дашборд-сетка: `N` колонок, блоки размером в целое число колонок и строк, перетаскивание, ресайз кратно сетке, раскладка в `localStorage` (`storageKey`) либо снаружи (`layout` + `onLayout`). Три режима (`mode`): `flow` (порядок, дырки остаются), `dense` (дырки затыкаются следующими блоками) и `free` (свои `{x,y}` — двигай куда хочешь, включая пустоту под последней строкой; дроп на занятое место отклоняется, соседей не расталкиваем). Разметка сетки — проп `showGrid` (`'drag'` по умолчанию, `true`, `false`): один элемент-подложка с CSS-градиентом, ширина колонки в `calc`, видимость через `opacity`. Запас пустых строк — `spareRows`, постоянный: расти во время драга он не может, иначе появление полосы прокрутки меняет ширину контента и сбивает шаг колонок посреди жеста. Ширина блока задаётся числом колонок ИЛИ пресетом-долей (`'full'`, `'half'`, `'third'`, `'quarter'`, `'two-thirds'`, `'three-quarters'`, любая дробь `'5/12'`) — то же в `minW`/`maxW`; доля округляется вниз, чтобы N блоков `1/N` влезали в строку. `createDumbGridGroup` — группа сеток: блок перетаскивается ИЗ ОДНОЙ сетки В ДРУГУЮ (`group` + `name` у компонента, `onTransfer` у группы, `accepts` у сетки, Esc отменяет). Для сеток это то же, чем `createSortableGroup` является для списков: один жест на группу, снимок контейнеров одним IntersectionObserver, зона под указателем по кэшированным прямоугольникам, клон в top layer (иначе блок обрезал бы `overflow` скроллящейся секции). Блок может быть контейнером — в том числе другой сеткой: блоки помечены `data-grid-block`, и сетка забирает жест, только если ближайший блок под указателем её собственный (сортировщик внутри блока разводится так же, по `data-flip-id`). Блоки рендерятся по `items`, а не по вычисленной раскладке, поэтому дроп не пересоздаёт DOM внутри них — скролл, фокус и вложенные ref'ы живы. Пример вложенных сеток — `examples/Board.example.tsx`. Проп `editable` (по умолчанию `true`) переключает режим редактирования: при `false` рисуется готовая сетка без ручек, кнопок, разметки и **без единого обработчика на блоках** — в отличие от `disabled`, который обвязку оставляет и лишь глушит жесты. Проп `onRemove` рисует на блоках кнопку ✕ (отключается на блоке через `removable: false`), а добавленный в `items` блок в свободном режиме получает первую свободную ячейку (`firstFreeCell`). Вместе с ним примитив `createDumbGrid`, движок без фреймворка `createGridEngine` и чистая математика сетки (`packFlow`, `cellRect`, `insertIndex`, `moveDeltas`, `snapSpan`, `colWidth`, `spanSize`, `rowCount`). Не `react-grid-layout`: свободных координат `{x,y}`, коллизий и компакции нет — блоки текут по порядку, поэтому раскладка это массив плюс два числа на блок. За жест ни одного замера по элементам: ширина колонки приходит из `ResizeObserver`, позиция контейнера — из `IntersectionObserver`, остальное арифметика. Ресайз показывается рамкой-превью, чтобы не перекладывать сетку покадрово.
- `Odata1C` — клиент стандартного интерфейса OData 1С (`OdataClient`, `createOdataClient`, `OdataError`, `odataString`, `toBase64`). Без зависимостей и без Solid, работает и в браузере, и в Node 18+. Умеет то, ради чего его и писали: обязательный `$format=…odata=nometadata`, пробелы как `%20` (с `+` 1С молча игнорирует `$filter`), разбор `odata.error` из-под BOM, таймаут запроса, точечное чтение `Entity(guid'…')` в обход запрета `$filter` и `tailPage()` — листание с конца для наборов, которые роль не даёт отсортировать.
- `DumbTable`: `spacerTop` / `spacerBottom` — пустые строки заданной высоты, если окно строк режется снаружи. Собственной виртуализации в ките нет: у `<table>` ширины колонок считаются по всем строкам, а `content-visibility` к `table-row` не применяется, поэтому нормальное окно — это отдельный компонент, а не проп. Пока рекомендуем пагинацию.

### Изменено
- `DumbGridDnd` переписан со стороны браузера: события ведёт Pragmatic, движение — наш FLIP, вместо индикатора видно место, куда встанет блок.

## [0.3.0] — 2026-07-29

### Добавлено
- `DumbTable`: `handle={false}` — строка тянется целиком, колонка с ручкой не рендерится; вместе с ним `dragThreshold`, чтобы клик и начало драга не путались.
- `DumbTable`: `rowStyle` — инлайн-стиль на строку (нужен, например, для уникального `view-transition-name`).
- `DumbTable`: `viewTransition` — анимировать клиентскую сортировку через View Transitions.
- `DumbTable`: третье положение сортировки — `asc → desc → без сортировки`; в серверном режиме сброс приходит как `onSort(null, null)`. Отключается пропом `noSortRemoval`.
- `DumbTable`: строки получают `data-key`, поэтому `SelectionArea` работает поверх таблицы без дополнительной возни.
- `animate` у `createDumbSortable`, `createSortableGroup`, `DumbSortable`, `DumbTree` и `DumbTable`: анимации отключаются, а без явного значения кит уважает системное `prefers-reduced-motion: reduce`.
- Приземление на дропе: элемент доезжает до нового места анимацией вместо телепорта (целевая позиция берётся из стартового снимка, ничего не меряется).
- Примеры: редактируемые ячейки в таблице, выделение поверх таблицы, кнопки «перемешать» и «удалить выделенное», длинный грид без `overflow`.

### Изменено
- **Ломающее:** сигнатура `onSort` в `DumbTable` расширена до `(key: string | null, order: 'asc' | 'desc' | null)` — сброс сортировки приходит как `(null, null)`.
- Движки жестов больше не зависят от Solid: `sortableCore`, `sortableGroup` и `selectionCore` принимают элементы и возвращают функции отписки, а `solid.ts` в каждой папке — тонкая обёртка над `onCleanup`. Публичный API не изменился.
- Примеры перевели с инлайн-стилей на классы и один `<style>` на файл — 117 инлайн-объектов стало 5, и те вычисляются из данных.
- Установка описана честно: пакета нет в npm, ставится с GitHub.

### Исправлено
- Строки съезжали на пару пикселей уже в момент захвата: накопительная раскладка опиралась на один усреднённый зазор. Перестановка описана как сдвиг блока — незатронутые строки получают ровно ноль.
- Драг больше не стартует с полей, кнопок, ссылок и `[contenteditable]`, а также пока фокус находится внутри строки (`document.activeElement`) — строку редактируют, а не двигают.
- Safari выделял текст во время жестов: не ставился `-webkit-user-select`, и подавление включалось только после порога, когда браузер уже что-то выделил. `ResizableGrid` болел тем же.
- `SelectionArea`: рамка не выезжает за контейнер (иначе растягивала ему `scrollWidth/Height` и добавляла полосы прокрутки на ходу).
- Стили при драге меняются только у тех строк, что реально едут: раньше `transition` и `will-change` вешались на весь список — сотня лишних записей и сотня композиторных слоёв.

## [0.2.0] — 2026-07-28

### Добавлено
- `DumbTable` + `DumbPagination` — таблица «принеси свои колонки» на `@tanstack/solid-table`: сортировка клиентская или серверная, перетаскивание строк, пагинация.
- `createSortableGroup` — перетаскивание **между** контейнерами (канбан): общий снимок всех зон, `accepts`, отмена по `Esc`, клон в top layer через Popover API.
- Демо: навигация по `hash` — на каждый пример есть прямая ссылка (`#kanban`), F5 не сбрасывает вкладку. Смоук-тесты монтируют все примеры.

### Изменено
- **Ломающее:** `SelectionArea` переписан на собственный движок, `@viselect/vanilla` удалён. Состояние теперь ваше: `selected` + `onChange` с обычным `Set<string>`, ключи читаются из `data-key`. Ушли `behaviour`/`features`/`boundaries`/`windowScroll` и тип `SelectionEvent`; таблица миграции — в [docs/SelectionArea.md](docs/SelectionArea.md).
- **Ломающее:** `dist/index.css` больше не собирается — рамка выделения рисуется инлайном, импортировать нечего.

### Исправлено
- Позиция вставки считалась по снятым позициям, хотя колонка уже раздвинута: дырка перескакивала раньше, чем курсор доходил до середины видимой карточки (и позже при движении вверх). Теперь расчёт идёт от текущей дырки по видимым позициям, гистерезис получается из геометрии.
- `sortableCore` звал `getBoundingClientRect` в каждом кадре — forced layout на горячем пути. Геометрия скроллера снимается один раз, в кадре читаются только `scrollTop/scrollLeft`.
- Выделение схлопывалось до видимой части при прокрутке — рамка теперь живёт в координатах контента.
- Сборка: `preset.writePackageJson()` переписывал `package.json` во время параллельной сборки, из-за чего зависимости иногда инлайнились в бандл (плавающий баг «через раз»).
