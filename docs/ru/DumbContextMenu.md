# DumbContextMenu и DumbPopover

Меню по правому клику и карточка у точки.

```tsx
import { DumbContextMenu, DumbPopover } from '@solid-dumb-kit/context-menu'
```

## Место выбирает браузер

Обычный способ узнать, куда раскрыться, — вставить меню, измерить
(`getBoundingClientRect`) и подвинуть. Это forced layout ровно в тот момент,
когда браузер и так занят.

Здесь два платформенных механизма и ни одного замера:

- **Popover API** (`popover="manual"`) — меню в **top layer**: над всем, включая
  чужие модалки, не режется `overflow` предков, не спорит за `z-index`;
- **anchor positioning** — в точке клика ставится невидимый якорь размером в
  пиксель, меню цепляется за него, а сторону у края окна выбирает браузер
  (`position-try-fallbacks`).

Грабля на этом пути: `position-area: bottom span-inline-end` Chrome молча
отбрасывает как невалидное, и меню уезжает в левый верхний угол. Привязка идёт
через `anchor()`.

## Жест как в macOS

Нажал правую кнопку, не отпуская повёл на пункт, отпустил — пункт сработал и меню
закрылось. Отпустил мимо — просто закрылось.

Привычка «щёлкнул — меню висит» при этом не ломается: короткое нажатие без
ведения оставляет меню открытым. Различаем по удержанию и расстоянию — **250 мс и
6 px**, те же пороги, что у долгого нажатия в остальном ките.

Тонкость: меню лежит в top layer, и `ev.target` при отпускании указывает куда
угодно, только не на пункт. Что под курсором, спрашиваем у браузера —
`document.elementFromPoint()`.

## Пункты

```tsx
<DumbContextMenu
  target={() => area}
  items={() => [
    { label: 'Открыть', icon: 'icon-[solar--eye-bold]', run: open },
    { label: 'Копировать', hint: '⌘C', run: copy },
    { kind: 'separator' },
    { label: 'Удалить', danger: true, disabled: !picked(), run: remove },
  ]}
/>
```

Пункты пересчитываются на каждое открытие — значит зависят от выделения. Стрелки
водят по пунктам (разделители и заблокированные пропускаются), Enter выбирает,
Esc закрывает, фокус уходит в меню и возвращается назад.

По полю ввода меню **не перехватывается**: там своё, браузерное, с «вставить».

## Подменю

Пункт с `items` — ветка: раскрывает панель вбок и сам ничего не делает, `run`
у него не нужен и не вызывается. Панель рекурсивна — вложенность любая.

```tsx
{ label: 'Экспорт', items: [
  { label: 'PNG', run: png },
  { label: 'SVG', run: svg },
  { label: 'Ещё…', items: [{ label: 'PDF', run: pdf }] },
] }
```

Подменю — такой же popover в top layer: его тоже не режет `overflow` предков и
ему не нужен `z-index`. Якорь у него **свой** — пиксель в точке, где курсор
вошёл в пункт-ветку, а не сама кнопка: кнопка лежит внутри родительского
popover, на элемент в top layer `anchor()` не разрешается, и панель уезжала бы
в статическую позицию. Сторону по-прежнему выбирает браузер, замеров
по-прежнему ноль — координаты берутся из события.

Поведение — как в системных меню:

- **мышью** ветка раскрывается наведением, наведение на обычный пункт закрывает
  чужую ветку;
- **с клавиатуры** подсветка ветку не раскрывает — открывают только `→` и
  Enter (с подсветкой первого пункта), `←` возвращает к родителю;
- **Esc** сворачивает по уровню: сначала подменю, с корня — всё меню;
- стрелки водят по **самой глубокой открытой** панели;
- жест press-drag-release продолжается в подменю: отпустил на ветке — меню
  остаётся, ведёшь дальше во вложенную панель.

## DumbPopover

То же место в top layer и та же привязка якорем, но содержимое произвольное:
`at`, `title`, `footer`, `children`. Нужен там, где модалка по центру рвёт связь
с тем, что описывает, — карточка брони должна стоять рядом с бронью.
