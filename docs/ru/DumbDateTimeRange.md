# DumbDateTimeRange

Период с временем: заезд 12 августа в 16:00 — выезд 15 августа в 12:00.

```tsx
import { DumbDateTimeRange, DumbTimeSelect, type Moment } from '@solid-dumb-kit/date-range'
```

## Две половины, а не один хитрый виджет

Сутки выбирает [`DumbDateRange`](DumbDateRange.md) — тот же календарь, та же
занятость, те же два клика или протяжка. Время выбирается отдельно, и в этом вся
разница между «работает» и «мучение»:

- **лента слотов** шагом `step` — занятый слот заштрихован и не нажимается, а
  период обводится нажатием и протяжкой, как в календаре;
- **списки** часов и минут (`mode="select"`) — когда шаг мелкий, места мало или
  дело происходит на телефоне, где `<select>` даёт родное колесо.

```tsx
const [when, setWhen] = createSignal<{ from: Moment; to: Moment } | null>(null)

<DumbDateTimeRange
  value={when}
  onChange={setWhen}
  busy={() => bookings}
  step={60}
  defaultFromTime="16:00"
  defaultToTime="12:00"
  minMinutes={12 * 60}
  onReject={(why) => toast.error(why)}
/>
```

## Момент — это пара строк

```ts
type Time = string                       // 'HH:mm'
type Moment = { day: Day; time: Time }   // day — 'YYYY-MM-DD'
```

Никакого `Date` в API. Причина та же, по которой день в `dateMath` — строка:
`new Date('2026-08-12 14:00')` разбирается в локальной зоне, и одно и то же
значение у сервера в UTC и у гостя во Владивостоке оказывается **разными
сутками**. Сравнение сводится к минутам: внутри одних суток хватает `toMin`,
между разными — `absMin`, которая добавляет номер дня относительно опорной даты.

## Стык — не конфликт

Гость выезжает в 12:00, следующий заезжает в 16:00 того же дня. День и занят, и
свободен одновременно — так работает любая гостиница, и компонент это допускает:
**касание концами пересечением не считается**. Слот — это отрезок
`[time, time + step)`, а не точка, поэтому начало брони, совпавшее с концом
соседней, занятым не выглядит.

## Протяжка

Нажал на слот, повёл, отпустил — период встал. Конец периода считается по **концу
последнего задетого слота**: обвёл один получасовой слот — получил полчаса, а не
нулевую длительность.

Протяжка **упирается в занятое**, а не проходит сквозь и не отменяется на
полпути. Что под курсором, компонент спрашивает у браузера раз в кадр:
`elementFromPoint` — это хиттест, ему нужна свежая раскладка, а подсветка
предыдущего слота её портит. Замеров слотов при этом ноль — ни одного
`getBoundingClientRect`.

Лента с протяжкой появляется, когда выбран **один** день. Многодневный период
показывает две группы слотов: заезд в своём дне, выезд в своём.

## Часы на календаре

Время заезда и выезда стоит прямо в крайних ячейках периода, а под календарём
лежит панель с обоими часами — править их можно, не сходя с календаря. Место под
панель отводится заранее: иначе она накрывала бы последнюю неделю месяца, и в
неё нельзя было бы ткнуть.

Свой угол дня (`dayExtra` — обычно цена) при этом остаётся: время подменяет его
только в двух крайних ячейках.

## Пропсы

| проп | тип | что делает |
| --- | --- | --- |
| `value` | `() => { from: Moment; to: Moment } \| null` | выбранный период |
| `onChange` | `(next) => void` | период собрался или сброшен |
| `busy` | `() => BusyMoment[]` | занятые отрезки: видны и не дают выбрать |
| `mode` | `'slots' \| 'select'` | лента слотов (по умолчанию) или списки |
| `step` | `number` | шаг слотов в минутах; по умолчанию 30 |
| `openMin` / `closeMin` | `number` | рабочее окно, минуты от полуночи: ночь вырезается |
| `defaultFromTime` / `defaultToTime` | `Time` | что подставить, когда день выбран, а слот ещё нет |
| `minMinutes` / `maxMinutes` | `number` | пределы длительности |
| `months` | `number` | сколько месяцев календаря; по умолчанию 1 |
| `min` / `max` | `Day` | границы дат; по умолчанию с сегодняшнего дня |
| `dayExtra` | `(day: Day) => JSX.Element` | своё в углу дня; на краях периода его сменяет время |
| `fromLabel` / `toLabel` | `string` | подписи; по умолчанию «Заезд» и «Выезд» |
| `onReject` | `(why: string) => void` | выбрать не вышло: причина словами |

## DumbTimeSelect

Время двумя списками — отдельный компонент, годится и без календаря.

```tsx
<DumbTimeSelect
  label="начало"
  value={time}
  onChange={setTime}
  step={30}
  openMin={9 * 60}
  closeMin={20 * 60}
  day={day()}
  busy={() => bookings}
/>
```

Занятость показывается прямо в списке: **полностью** занятый час помечен и не
выбирается. Именно полностью — иначе список начнёт врать: внутри часа может
оставаться свободные полчаса.

## Математика отдельно от разметки

`timeMath` отдаётся наружу целиком: занятость приходится проверять и на сервере
перед записью в базу, и в тесте.

| функция | что делает |
| --- | --- |
| `toMin` / `toTime` | `HH:mm` ↔ минуты; за сутки не переносит (1500 → `25:00`) |
| `absMin` / `fromAbsMin` | момент ↔ минуты относительно опорного дня |
| `minutesBetween` | длительность между моментами |
| `slotsOfDay` | нарезать сутки шагом, не включая конец окна |
| `slotBusy` | занят ли слот; касание концами не в счёт |
| `overlapsMoment` | пересекаются ли отрезки |
| `reachToMoment` | докуда можно тянуть, не задев занятое |
| `checkMomentRange` | полная проверка периода; отказ — фразой для человека |
| `snapTime` | округлить вниз до шага сетки |
| `fmtLength` / `fmtMoment` | «1 ч 30 мин», «12.08 14:00» |
