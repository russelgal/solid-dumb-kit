# DumbFinder

Файловый менеджер по чужому хранилищу: папки, выделение рамкой, заливка броском,
перенос перетаскиванием.

Собран из готового: выделение — [`SelectionArea`](SelectionArea.md) кита (один
снимок на жест, ноль замеров элементов), заливка — та же очередь, что у
[`DumbGallery`](DumbGallery.md), перенос — нативный HTML5 drag-and-drop.

**Компонент ничего не знает про S3.** Он спрашивает у `source` содержимое папки и
просит что-нибудь с ним сделать — весь договор. За ним может стоять что угодно:
бакет, диск, база, WebDAV, IndexedDB.

## Как это работает

**Папка — это ключ, заканчивающийся на `/`.** Никаких папок в S3 нет вовсе, есть
общий префикс, и файндер эту условность разделяет: `a/b/` — папка, `a/b` — файл,
а корень — пустая строка, а не `/`. Из этого растёт всё остальное: крошки,
«перенести внутрь», «папку в саму себя нельзя».

**Выделение не стоит ни одного layout.** Рамка — это `SelectionArea`: позиции
снимаются один раз на жест через `IntersectionObserver`, а в кадре только
арифметика. Клик выбирает один, Shift/Cmd/Ctrl добавляет или снимает,
Ctrl/Cmd+A берёт всё, Esc снимает.

**Перенос — нативный драг.** Тащишь выделенное на папку — или на крошку пути,
так выкидывают уровнем выше. Расплата за нативный жест: **пальцем не работает**,
HTML5 drag-and-drop на тачскрине не существует. Всё остальное — ходить по
папкам, выделять, заливать, удалять — работает.

**Дерево папок слева — своё**, разметка и стили лежат в том же файле. Сначала
стоял `DumbTree`, и его убрали: он размечен под Tailwind/daisyUI, и половина
работы уходила на гашение чужих отступов, прокруток и линий уровней. Строка
дерева — ещё и цель переноса: перенести через полбакета, не открывая его.
Границу между деревом и файлами тянут мышью — это
[`ResizableGrid`](ResizableGrid.md), поэтому ширина запоминается.
`sidebar={false}` выключает колонку целиком.

**Дерево папок читается целиком и сразу**, если источник так умеет. У S3 это
один рекурсивный листинг без `Delimiter`, и папки выводятся из ключей
арифметикой — дешевле, чем запрос на ветку, и заодно даёт то, чего перечисление
по уровню дать не может: **сколько папка весит**. Объём и число файлов — суммы
по всему вложенному, показываются и в дереве, и рядом с папкой в списке. Нет
`source.tree` — дерево грузится по веткам, а вес у папок не показывается вовсе:
лучше пусто, чем цифра, которая врёт.

**В списке папка раскрывается прямо в строке** — треугольник, и содержимое
встаёт следующими строками с отступом. Ровно то, что делает настоящий Finder, и
ровно то, ради чего список вообще нужен: заглянуть в три папки разом, не теряя,
где ты был. В плитках раскрытия нет — его нет и в Finder.

**Значки — CSS-классы, которые даёшь ты**, а не разметка, зашитая в пакет:
Solar, Phosphor, Lucide — что соберёт твой Tailwind/iconify. Не задал — рисуются
эмодзи, чтобы пакет работал и без иконочного набора вовсе.

**Заливка идёт очередью.** По нескольку файлов разом, остальные ждут; снятая
плитка обрывает запрос. Бросок файлов **на папку** кладёт их внутрь неё, а не в
ту, которую сейчас смотришь.

**Список перечитывается, а не подправляется.** После каждого изменения файндер
снова зовёт `source.list`, вместо того чтобы гадать, что там сделало хранилище.
Щёлкать по папкам быстрее, чем оно отвечает, безопасно: незаконченное
перечисление обрывается, и позапрошлый ответ не ляжет поверх свежего.

## Ключей от хранилища файндер не видит

Правило то же, что у галереи, и по той же причине: ключ к бакету — ключ ко
**всему бакету**. В браузере ему не место, значит наружу ходим через свой сервер
— а раз через сервер, хранилище за ним может быть каким угодно.

```tsx
import { DumbFinder, type FinderSource } from '@solid-dumb-kit/finder'
import { putWithProgress } from '@solid-dumb-kit/shared'

const source: FinderSource = {
  list: (prefix, { signal }) =>
    fetch(`/api/s3/list?prefix=${encodeURIComponent(prefix)}`, { signal })
      .then((r) => r.json())
      .then((r) => r.entries),

  upload: async (file, ctx) => {
    const signed = await fetch('/api/sign', {
      method: 'POST',
      body: JSON.stringify({ name: file.name, type: file.type, prefix: ctx.prefix }),
    }).then((r) => r.json())
    await putWithProgress(file, signed, ctx)      // XHR, поэтому полоса реально едет
  },

  remove: (keys) => post('/api/s3/delete', { keys }),
  move: (keys, to) => post('/api/s3/move', { keys, to }),
  mkdir: (prefix) => post('/api/s3/mkdir', { prefix }),
}

<DumbFinder source={source} onOpen={(e) => window.open(e.url, '_blank')} />
```

**Каждое умение необязательно.** Нет `remove` — нет кнопки удаления. Нет `move` —
плитки вообще не таскаются. Смотрелка «только чтение» — это `source`, в котором
один `list`.

## Готовые адаптеры

Писать адаптер руками — исключение, а не правило: четыре идут в пакете.

| адаптер | как ходит | заливка |
| --- | --- | --- |
| `createS3Source` | свои ручки к S3-совместимому (Garage, MinIO, AWS) | сервер подписывает ссылку, файл летит **в бакет мимо сервера** |
| `createNodeSource` | тот же набор ручек у простого сервера с папками на диске | файл идёт **через сервер**, телом запроса, без multipart |
| `createWebdavSource` | сам протокол: `PROPFIND` / `MKCOL` / `MOVE` / `DELETE` | `PUT` по адресу файла |
| `createMemorySource` | в памяти вкладки, ключи плоские как в S3 | эмулируется, с прогрессом |

```tsx
import { DumbFinder, createS3Source } from '@solid-dumb-kit/finder'

<DumbFinder source={createS3Source({ base: '/api/s3', sign: '/api/sign' })} />
```

Под первыми двумя лежит общий `createHttpSource` — он тоже наружу: пригодится,
если ручки называются иначе (`paths`), нужны заголовки авторизации (`headers`)
или сервер чего-то не умеет (`without: ['move']` — и плитки перестают
таскаться).

WebDAV прямо со страницы работает, только если сервер отдаёт CORS с этими
глаголами и с `Authorization`; чужой публичный обычно не отдаёт. Тогда ставь его
за свой прокси и бери `createHttpSource`.

## Что должен уметь сервер

`list` — это `ListObjectsV2` с `Delimiter: '/'`: именно этот параметр превращает
плоский бакет в дерево, `CommonPrefixes` — папки, `Contents` — файлы этого
уровня.

Остальное менее очевидно, и плагин витрины (`playground/devS3.ts`) делает это всё:

- **Удаление папки удаляет её содержимое.** Пустых папок в S3 не бывает, и
  «удалить папку, оставив файлы» означало бы осиротить их навсегда.
- **Перенос — это копирование плюс удаление**, ключ за ключом, по всему
  поддереву. `CopySource` кодируется **посегментно**: прогонишь строку целиком
  через `encodeURIComponent` — слэши станут `%2F`, и часть хранилищ такой
  источник не найдёт.
- **Создание папки — это запись пустого объекта с ключом на `/`.** Иначе
  только что созданная папка в списке не появится: в ней нечему породить
  `CommonPrefix`.

## Как проверить на живом хранилище

В витрине это собрано — **только для разработки**. `pnpm demo` поднимает у себя
`/api/s3/*` и `/api/sign` (плагин `playground/devS3.ts`, `apply: 'serve'`),
подписанные ключами из корневого `.env`. В собранной витрине и на Pages сервера
нет, поэтому вкладка работает на хранилище в памяти вкладки с тем же поведением.

```bash
cp .env.example .env      # S3_ENDPOINT, S3_BUCKET, ключи
pnpm demo                 # печатает «дев-подпись: <бакет> на <endpoint>, запись во весь бакет»
```

**Запись идёт по всему бакету** — это дев-ручки к своему же хранилищу, и запирать
хозяина в песочнице незачем: файндер для того и нужен, чтобы разбирать настоящие
папки. Помнить стоит одно: отмены нет, удаление тут пачками. Нужен
предохранитель (общий бакет, чужие данные) — `S3_DEV_LOCK` в `.env` запирает
запись: `1` означает префикс `dumb-kit-dev/`, любая другая строка идёт как сам
префикс. Уборка:

```bash
pnpm dev:s3:clean         # посмотреть
pnpm dev:s3:clean --yes   # удалить
```

Проверено на живом Garage: листинг всего дерева с весами папок, создание папки,
перенос файла внутрь и обратно, удаление папки, сортировка по размеру и по дате
— в том числе с кириллицей в именах.

## Пропсы

| проп | тип | что делает |
| --- | --- | --- |
| `source` | `FinderSource` | чем говорить с хранилищем; единственный обязательный |
| `path` | `string` | открытая папка; не задан — файндер водит себя сам |
| `onPathChange` | `(prefix) => void` | перешли в другую папку |
| `selected` | `Set<string>` | выделение; не задан — держит у себя |
| `onSelectionChange` | `(keys) => void` | выделение изменилось |
| `view` | `'grid' \| 'list'` | плитками или строками; не задан — переключатель в тулбаре |
| `onViewChange` | `(view) => void` | вид переключили |
| `accept` | `string` | что пускать в выбор файлов |
| `concurrency` | `number` | сколько заливок разом, по умолчанию `3` |
| `rootLabel` | `string` | как зовётся корень в крошках, по умолчанию `Всё` |
| `tile` | `string` | ширина плитки, css-трек; по умолчанию `minmax(132px, 1fr)` |
| `height` | `string` | высота области с файлами, по умолчанию `60vh` |
| `sidebar` | `boolean` | дерево папок слева; `false` — выключить |
| `sidebarWidth` | `string` | стартовая ширина дерева; дальше её тянут мышью и она запоминается |
| `treeKey` | `string` | ключ `localStorage` для раскрытых веток и ширины колонок, по умолчанию `dumb-finder` |
| `icons` | `Partial<Record<FileKind \| 'dir' \| 'dirOpen' \| 'twist' \| 'refresh' \| 'viewGrid' \| 'viewList' \| 'mkdir' \| 'upload' \| 'remove', string>>` | классы значков: виды файлов, стрелка, кнопки тулбара |
| `editable` | `boolean` | `false` — только смотреть, что бы ни умел `source` |
| `onOpen` | `(entry) => void` | двойной клик по файлу (по папке ходит сам) |
| `onError` | `(message) => void` | не смогли перечислить, залить, удалить, перенести |
| `children` | `(entry, ctx) => JSX.Element` | своя плитка |

### FinderEntry

| поле | смысл |
| --- | --- |
| `key` | полный путь от корня; у папки **обязательно** заканчивается на `/` |
| `name` | что писать под значком |
| `dir` | папка ли это |
| `size` | размер файла; у папки — сумма по всему вложенному |
| `count` | сколько файлов внутри; только у папок |
| `modified` | мс или что угодно, что понимает `Date.parse` |
| `url` | чем показывать превью и что достаётся `onOpen` |

### FinderSource

| метод | если не задан |
| --- | --- |
| `list(prefix, { signal })` | обязателен |
| `tree({ signal })` | дерево грузится по веткам, вес папок не показывается |
| `upload(file, { prefix, onProgress, signal })` | заливки нет вовсе |
| `remove(keys)` | нет кнопки удаления |
| `move(keys, toPrefix)` | плитки не таскаются |
| `mkdir(prefix)` | нет «новой папки» |

## Клавиши

| клавиша | что делает |
| --- | --- |
| `Backspace` | на уровень выше |
| `Delete` | удалить выделенное (с подтверждением в тулбаре) |

## Почему подтверждение в тулбаре

`confirm()` блокирует вкладку целиком — идущая заливка встаёт вместе с ней, —
выглядит чужим в любой теме, и написать в нём, что именно сейчас удалится,
нельзя. Поэтому вопрос — строка в тулбаре, с перечислением имён.

## Тащат плитку или бросают файлы

И то и другое — нативный drag-and-drop, и их надо различать. Файндер делает это
по `dataTransfer.types`: у файлов там `Files`, у плитки нет. От этого зависит,
загорится ли папка как «перенести сюда» или вся область как «брось файлы сюда».

Ещё тонкость, если рисуешь свою плитку: жест, начатый на **уже выделенной**
плитке, рамку не запускает. Браузер на старте нативного драга шлёт
`pointercancel`, а движок выделения счёл бы это кликом и схлопнул выделение до
одной плитки — ровно в тот момент, когда ты потащил их все.

## Чистая часть

Пути и порядок — обычные функции, наружу выложены потому, что делить те же ключи
придётся и в твоём адаптере:

```ts
import { crumbs, nameOf, parentOf, canMove, sortEntries, kindOf } from '@solid-dumb-kit/finder'

nameOf('a/b/c.jpg')        // 'c.jpg'
parentOf('a/b/c.jpg')      // 'a/b/'
crumbs('a/b/')             // [{ name: 'Всё', prefix: '' }, { name: 'a', … }, …]
canMove('a/b/', 'a/b/c/')  // false — папку внутрь своего же потомка нельзя
kindOf('photo.WEBP')       // 'image'
```

`sortEntries` держит папки сверху даже при сортировке по размеру, а имена
сравнивает с `numeric: true` — иначе `файл10` встаёт перед `файл2`, и это
замечают сразу.
