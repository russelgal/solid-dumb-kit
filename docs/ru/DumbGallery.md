# DumbGallery

Картинки: выбрать, посмотреть, переставить, залить.

Собран из готового: выбор файлов и приём их броском в окно — примитив
[`@solid-primitives/upload`](https://primitives.solidjs.community/package/upload),
перестановка — [`DumbSortable`](DumbSortable.md) (указательный движок, работает
и пальцем), заливка — очередь с транспортом, который даёшь ты.

## Как это работает

**Картинка появляется сразу.** Выбранный файл показывается из `objectURL`, не
дожидаясь никакой заливки. Без транспорта галерея на этом и живёт — получается
локальный набор, который никуда не уходит.

**Заливка идёт очередью.** Двадцать файлов не полетят двадцатью запросами:
браузер всё равно держит к одному хосту около шести соединений, и двадцать
«идущих» полосок, из которых движутся шесть, просто врут. Очередь запускает по
нескольку, остальные ждут со статусом `queued` и умеют выброситься мгновенно —
снятая плитка **обрывает** запрос, а не досчитывает его в никуда.

**Порядок — твои данные.** Компонент ничего не хранит: добавили, переставили,
удалили, долилось — каждое изменение уходит в `setItems`.

## Ключей от хранилища галерея не видит

Ключ к бакету — это ключ **ко всему бакету**: удалить, перезаписать, вычитать
чужое. В браузере ему не место ни в каком виде — ни в переменных сборки, ни
«только на время». Его место на сервере, а браузеру достаётся ссылка,
подписанная на один объект и на несколько минут.

Поэтому галерея не знает ни про бакет, ни про регион, ни про эндпоинт. Наружу
она ходит ровно за одним — за подписью:

```tsx
import { DumbGallery, createPresignedUploader } from '@solid-dumb-kit/gallery'

const upload = createPresignedUploader({
  sign: (file) =>
    fetch('/api/sign', {
      method: 'POST',
      body: JSON.stringify({ name: file.name, type: file.type }),
    }).then((r) => r.json()),   // → { url, headers?, key?, publicUrl? }
})

<DumbGallery items={items()} setItems={setItems} upload={upload} />
```

Подписывает — твой сервер. Для Garage (и любого S3-совместимого) это
`getSignedUrl` из `@aws-sdk/s3-request-presigner`:

```ts
// на сервере, ключи только здесь
const url = await getSignedUrl(
  s3,                                   // S3Client с endpoint и forcePathStyle
  new PutObjectCommand({ Bucket, Key: key, ContentType: type }),
  { expiresIn: 300 },
)
return { url, key, publicUrl: `${PUBLIC_BASE}/${key}` }
```

**Заголовки из подписи обязательно повторить один в один.** Подписали
`ContentType` — значит браузер должен отдать ровно тот же `Content-Type`, иначе
хранилище ответит `403`. Для этого в ответе и есть `headers`.

### Почему XHR, а не fetch

У `fetch` нет прогресса отдачи: `ReadableStream` в теле запроса поддерживают не
все, а где поддерживают — требуется HTTP/2 и `duplex: 'half'`.
`XMLHttpRequest.upload.onprogress` работает везде и ровно для этого и
существует. Внутри `createPresignedUploader` — он.

## Свой транспорт

`upload` — обычная функция. Хочешь класть через свою ручку, а не в S3 —
напиши её сам:

```ts
const upload: Uploader = async (file, { onProgress, signal }) => {
  const body = new FormData()
  body.append('file', file)
  const res = await fetch('/api/upload', { method: 'POST', body, signal })
  if (!res.ok) throw new Error(`сервер ответил ${res.status}`)
  return await res.json()      // → { url, key? }
}
```

Прогресс тут не поедет (см. выше), всё остальное работает как обычно.

## Пропсы

| проп | тип | что делает |
| --- | --- | --- |
| `items` | `Array<GalleryItem>` | набор; порядок массива = порядок на экране |
| `setItems` | `(next) => void` | новый набор: добавили, переставили, удалили, долилось |
| `upload` | `Uploader` | чем заливать; не задан — галерея локальная |
| `concurrency` | `number` | сколько тянуть одновременно, по умолчанию `3` |
| `accept` | `string` | что пускать в выбор, по умолчанию `image/*` |
| `multiple` | `boolean` | можно ли выбрать несколько разом |
| `max` | `number` | больше стольких не принимать |
| `tile` | `string` | ширина плитки, css; по умолчанию `minmax(120px, 1fr)` |
| `editable` | `boolean` | правка; при `false` нет ни выбора, ни перестановки, ни удаления |
| `animate` | `boolean` | анимировать перестановку |
| `onOpen` | `(item, index) => void` | клик по плитке |
| `children` | `(item, index) => JSX.Element` | своя плитка целиком |

### GalleryItem

| поле | что значит |
| --- | --- |
| `id` | обязателен, стабильный |
| `url` | где картинка живёт по-настоящему (после заливки) |
| `preview` | `objectURL` выбранного файла; показывается, пока он есть |
| `name`, `size` | из файла |
| `status` | `local` · `queued` · `uploading` · `done` · `error` |
| `progress` | `0…1`, пока идёт заливка |
| `error` | сообщение, если упало |
| `key` | ключ в хранилище — приходит из транспорта |

## Очередь отдельно

`createUploadQueue` не знает ни про DOM, ни про Solid — если рисуешь свою
галерею, возьми только её:

```ts
const q = createUploadQueue(upload, { onStart, onProgress, onDone, onError }, 3)
q.add(id, file)
q.cancel(id)     // ждущего выбросит, идущего прервёт
q.destroy()      // на размонтировании
```

## Чего он не делает

- **Не режет и не жмёт картинки.** Хочешь превью поменьше — это `imgproxy` или
  что угодно на твоей стороне; в ките для адресов есть `imgproxyUrl` из
  `@solid-dumb-kit/utils`.
- **Не открывает просмотр.** `onOpen` зовётся, а лайтбокс твой.
- **Не хранит порядок.** `items` — твой массив, персист тоже твой.
- **Не повторяет упавшее само.** Статус `error` виден, а решение повторять —
  твоё: позови `upload` для тех же файлов ещё раз.
