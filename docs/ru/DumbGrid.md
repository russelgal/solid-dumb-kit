# DumbGrid

**Дашборд-сетка** для SolidJS: `N` колонок, блоки размером в **целое число колонок и строк**, перетаскиваемые для смены порядка и ресайзимые кратно сетке, с персистом раскладки в `localStorage`. **Ноль замеров элементов за жест.**

```tsx
import { DumbGrid, createDumbGrid } from 'solid-dumb-kit'
```

Две формы:

- **`DumbGrid`** — компонент: отдал `items`, получил работающий дашборд;
- **`createDumbGrid`** — примитив (ручные ref'ы), когда разметка должна быть твоя.

CSS не нужен: движение — инлайн `transform`, позиции — инлайн `grid-column` / `grid-row`.

## Три режима раскладки

| `mode` | Откуда позиция | Дырки | Что делает драг |
|---|---|---|---|
| `flow` (по умолчанию) | индекс в массиве | остаются там, где их оставил широкий блок | меняет порядок |
| `dense` | индекс в массиве | затыкаются следующими блоками | меняет порядок |
| `free` | свои `{x, y}` блока | остаются ровно там, где ты их оставил | переносит в ячейку |

```tsx
<DumbGrid mode="dense" items={items} />
<DumbGrid mode="free" showGrid items={items} />
```

`flow` и `dense` — одна и та же одномерная модель, разница лишь в том, можно ли укладчику вернуться назад и заткнуть дырку. `free` — режим «ставь куда хочешь»: тащишь блок в пустое место под последней строкой, там он и остаётся.

В режиме `free` дроп на занятое место **отклоняется** — рамка краснеет, блок улетает домой. Соседей не расталкиваем никогда: каскадные сдвиги ломают ровно ту предсказуемость, ради которой свободный режим и включают. Ресайз обрезается по реально свободному месту (`fitSpan`): блок растёт, пока не упрётся в соседа.

## Чем это НЕ является

Даже в режиме `free` это **не** `react-grid-layout`: ни проходов компакции, ни каскада коллизий здесь нет. В `flow`/`dense` блоки текут по порядку, как при `grid-auto-flow: row`: раскладка — одномерный массив плюс два числа на блок.

Ограничение — оно и есть смысл:

| | react-grid-layout | DumbGrid |
|---|---|---|
| Модель | `{i, x, y, w, h}` + компакция | упорядоченный массив + `{w, h}` (+ `{x, y}` в `free`) |
| Перестановка | пересчёт укладки | `splice` |
| Что сохраняем | вся раскладка на каждый breakpoint | `[{id, w, h, x?, y?}]` |
| Замеров в кадре | `getBoundingClientRect` на элемент | ни одного |

Если нужны произвольные дырки («этот блок стоит в колонке 7, строке 4, и пустоту рядом никто не занимает») — это `mode="free"`, он ровно для этого. Чего не будет ни в одном режиме, так это расталкивания соседей, чтобы освободить место: вместо этого дроп отклоняется.

## Почему не дёргается

Раз размеры целые, а ширина колонки известна, **любая позиция считается арифметикой** — мерить нечего. За весь жест кит обращается к layout ровно дважды, и оба раза не по блокам:

1. `ResizeObserver` на контейнере — ширина контента (браузер отдаёт сам, без reflow; оттуда же padding: `contentRect.left/top`);
2. `IntersectionObserver` на контейнере при старте жеста — его позиция во вьюпорте (`boundingClientRect` считается off-main-thread, без reflow).

Дальше в кадре только чтение `scrollTop`/`scrollLeft` и запись `transform`. Стоимость драга не зависит от количества блоков на экране.

Соседи расступаются **вычитанием двух раскладок**: укладываем текущий порядок, укладываем порядок с перетаскиваемым на новом месте — разница и есть `dx/dy` каждого блока. Перенос блока на другую строку получается даром.

Ресайз показывается **пунктирной рамкой-превью**, а не живым изменением блока: менять `width`/`height` покадрово значило бы перекладывать всю сетку каждый кадр. Рамка — один элемент, и её размер пишется только когда снап реально сменился.

## Компонент `DumbGrid`

```tsx
import { DumbGrid } from 'solid-dumb-kit'

<DumbGrid
  cols={12}
  rowHeight={92}
  gap={12}
  storageKey="dashboard"
  items={[
    { id: 'revenue', w: 'half', h: 2, minW: 'quarter', content: () => <Revenue /> },
    { id: 'orders',  w: 'quarter',    content: () => <Kpi value="1 284" /> },
    { id: 'stock',   w: 3, h: 2,      content: () => <LowStock /> },
    { id: 'pinned',  w: 'quarter', locked: true, content: () => <Pinned /> },
  ]}
/>
```

Блок тянется за любое место, либо добавь `data-drag-handle` дочернему элементу — тогда тянуть можно только за ручку:

```tsx
{ id: 'revenue', w: 6, h: 2, content: () => (
  <div class="card">
    <div class="card-head" data-drag-handle>⠿ Выручка</div>
    <Chart />
  </div>
) }
```

Без ручки нажатия на `input`, `button`, `a`, `select`, `label`, `[contenteditable]` и `[data-no-drag]` драг не начинают — как и любое нажатие, пока внутри блока что-то в фокусе.

### Пропы

| Проп | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `items` | `DumbGridItem[]` | — | блоки; `content` — render prop |
| `mode` | `'flow' \| 'dense' \| 'free'` | `'flow'` | как раскладывать блоки (см. выше) |
| `cols` | `number` | `12` | колонок в сетке (реактивно — передавай значение сигнала) |
| `rowHeight` | `number` | `80` | высота строки, px |
| `gap` / `gapX` / `gapY` | `number` | `12` | зазоры; осевые сильнее общего |
| `storageKey` | `string` | — | ключ `localStorage`; без него раскладка живёт в памяти |
| `layout` | `DumbGridLayout` | — | контролируемый режим: раскладку держишь ты |
| `onLayout` | `(l: DumbGridLayout) => void` | — | вызывается после каждой перестановки/ресайза |
| `onRemove` | `(id: string) => void` | — | задал — на блоках появляется кнопка ✕ |
| `labels` | `{ remove?, resize? }` | ru | подписи кнопок (title / aria-label) |
| `resizable` | `boolean` | `true` | показывать ручки ресайза |
| `editable` | `boolean` | `true` | `false` → голая сетка: ни обвязки, ни обработчиков |
| `disabled` | `boolean` | `false` | жесты выключены, обвязка редактора остаётся |
| `animate` | `boolean` | `true`\* | анимировать расступание и приземление |
| `pressDelay` | `number` | `350` | тач: удержание до старта драга, мс |
| `mouseThreshold` | `number` | `0` | мышь: дистанция до старта драга, px |
| `showGrid` | `boolean \| 'drag'` | `'drag'` | рисовать разметку сетки: во время жеста / всегда / никогда |
| `spareRows` | `number` | `2` в `free`, `0` в потоке | пустые строки под раскладкой, чтобы блок было куда увести в пустоту |
| `class` / `style` | — | — | на контейнере сетки |
| `blockClass` / `blockStyle` | — | — | на обёртке каждого блока |

\* по умолчанию анимации уважают `prefers-reduced-motion: reduce`; явное `animate={true}` перебивает и её.

## Вложенные сетки

Блок может быть сеткой сам. Внешняя раскладывает секции, у каждой секции — свой `DumbGrid` со своими колонками, шагом строки и раскладкой:

```tsx
<DumbGrid cols={12} rowHeight={104} items={sections().map((sec) => ({
  id: sec.id, w: 6, h: 4,
  content: () => (
    <section>
      <header data-drag-handle>⠿ {sec.title}</header>
      <DumbGrid cols={6} rowHeight={56} items={widgetsOf(sec.id)} />
    </section>
  ),
}))} />
```

Уровни не дерутся за указатель: каждый блок помечен `data-grid-block`, и сетка забирает жест, только если **ближайший** блок под указателем — её собственный. Поэтому нажатие на вложенный виджет принадлежит внутренней сетке, а секция тянется за свою шапку.

То же правило закрывает сортировщик внутри блока (`createDumbSortable` или канбан-колонку из `createSortableGroup`): его элементы помечены `data-flip-id`, и сетка их тоже пропускает.

Что важно помнить: **`items` не должен зависеть от вложенного состояния**. Выводи его только из списка блоков (`createMemo` по секциям), чтобы перестановка внутри не пересобирала внешние items посреди чужого жеста. Блоки рендерятся по `items`, а не по вычисленной раскладке, ровно затем, чтобы дроп никогда не пересоздавал DOM внутри них — скролл, фокус и вложенные ref'ы переживают перестановку.

Смотри `examples/Board.example.tsx`: два уровня, контролируемые раскладки на обоих, плюс добавление и удаление секций и виджетов.

## Режим редактирования

Дашборд правят изредка, а смотрят постоянно — поэтому редакторская обвязка это режим, а не постоянная деталь:

```tsx
const [edit, setEdit] = createSignal(false)

<DumbGrid editable={edit()} items={items} onRemove={remove} />
```

При `editable={false}` компонент рисует **готовую сетку и ничего больше**: ни ручек ресайза, ни кнопок ✕, ни разметки сетки, ни `cursor`/`touch-action`, ни единого обработчика на блоках. Блоки остаются ровно там же, где были: позиции считаются одной и той же арифметикой в обоих режимах.

Это сознательно сильнее, чем `disabled`:

| | `disabled` | `editable={false}` |
|---|---|---|
| Редакторская обвязка | рисуется | не рисуется |
| Обработчики на блоках | висят, жесты отклоняются | не навешиваются |
| Подложка сетки | рисуется, скрыта | не рисуется |
| Запас строк снизу | держится | не нужен |
| Когда нужен | идёт сохранение | боевой экран |

Переключение флага пересоздаёт блоки (иначе ref'ы не навесить и не снять), поэтому обратно всё возвращается целиком.

## Пресеты размеров

Ширина принимает **число колонок или долю сетки** — равноправно и то, и то:

```tsx
{ id: 'hero',  w: 'full', h: 2 }        // вся ширина, две строки
{ id: 'chart', w: 'half' }              // половина колонок
{ id: 'kpi',   w: 'quarter' }
{ id: 'odd',   w: '5/12' }              // любая дробь
{ id: 'exact', w: 7 }                   // произвольные числа работают как раньше
```

Пресеты: `full`, `half`, `third`, `quarter`, `two-thirds`, `three-quarters` плюс любая дробь `'n/d'`. Работают и в `minW`/`maxW` (`minW: 'quarter'`).

Доля округляется **вниз**, поэтому N блоков ширины `1/N` всегда влезают в строку, даже если сетка на доли не делится (`half` от 5 колонок — это 2, а не 3). Пресет считается от текущего `cols`, так что один и тот же блок будет 6 колонок на 12-колоночной сетке и 3 на шестиколоночной. Неизвестная строка даёт 1 колонку — опечатка должна бросаться в глаза, а не тихо растягивать блок на всю ширину.

`h` остаётся числом строк: строки ничем не ограничены, брать от них долю не от чего.

## Добавление и удаление блоков

Набором блоков владеешь ты — источник истины это `items`, поэтому добавить блок значит просто дописать его в свой массив. Кит берёт на себя другое: убрать за исчезнувшим блоком и найти место появившемуся:

```tsx
const [items, setItems] = createSignal(initial)

const add = () => setItems((l) => [...l, { id: `w-${l.length}`, w: 'half', content: () => <New /> }])

<DumbGrid items={items()} onRemove={(id) => setItems((l) => l.filter((i) => i.id !== id))} />
```

- `onRemove` — задал, и на каждом блоке появляется кнопка ✕; отдельному блоку это отключает `removable: false` (удобно для закреплённых). Кнопка — `<button data-no-drag>`, поэтому нажатие на неё никогда не начинает драг. Стилизуется через `[data-grid-remove]`, подпись меняется через `labels.remove`.
- Блока не стало в `items` — он уходит и из раскладки, и из стора.
- Новый блок дописывается в конец в порядке `items`. В режиме `free` он ещё и получает **первую свободную ячейку** (`firstFreeCell`), чтобы лечь в первую дырку, а не поверх соседа; явные `x`/`y` это переопределяют.

### `DumbGridItem`

| Поле | Тип | Смысл |
|---|---|---|
| `id` | `string` | стабильная идентичность — ключ персиста |
| `content` | `() => JSX.Element` | render prop |
| `w` | `number \| SpanPreset` | начальная ширина: колонки или доля (по умолчанию `1`) |
| `h` | `number` | начальная высота в строках (по умолчанию `1`) |
| `x` / `y` | `number` | начальная ячейка в режиме `free`; не задал — уложим потоком |
| `minW` / `maxW` | `number \| SpanPreset` | пределы ширины: колонки или доля |
| `minH` / `maxH` | `number` | пределы высоты в строках |
| `locked` | `boolean` | ни двигать, ни ресайзить (от соседей всё равно поедет) |
| `removable` | `boolean` | показывать кнопку ✕ у этого блока (по умолчанию да, если задан `onRemove`) |

## Видимая сетка

`showGrid` рисует карту ячеек на **одном** элементе-подложке — никаких узлов на каждую ячейку:

```tsx
<DumbGrid showGrid items={items} />        {/* всегда */}
<DumbGrid showGrid="drag" items={items} /> {/* только во время жеста (по умолчанию) */}
<DumbGrid showGrid={false} items={items} />
```

Ширина колонки в этом фоне не меряется из JS — это `calc((100% - зазоры) / cols)`, поэтому браузер считает её сам и линии остаются верными при любом ресайзе окна. Видимость переключается через `opacity` (композитная), так что включение сетки на старте жеста ничего не перекладывает.

## Полосы прокрутки: держи место всегда

Запас пустых строк (`spareRows`) **постоянный**, а не «добавим на время драга». Иначе высота контейнера растёт в момент старта жеста, у страницы появляется полоса прокрутки, ширина контента уменьшается на её толщину — и `ResizeObserver` честно пересчитывает шаг колонок посреди жеста, из-за чего блоки едут сами по себе.

По той же причине сам контейнер сетки просит `scrollbar-gutter: stable`, а странице это стоит задать у себя:

```css
html { scrollbar-gutter: stable }
```

## Персист

С `storageKey` раскладка хранится как `[{id, w, h, x?, y?}]` — вместе с порядком, потому что в потоковых режимах порядок *и есть* позиция; в режиме `free` координаты пишутся **всем** блокам сразу, чтобы на следующем дропе ничего не прыгнуло.

`storageKey` читается при монтировании. Меняешь стор на ходу (например, по одному на режим) — перемонтируй компонент, хватит `<Show when={mode()} keyed>`.

Сохранённый снимок всегда сливается с текущими `items` (`mergeLayout`, экспортирован для тестов):

- блоки, исчезнувшие из `items`, выбрасываются;
- блоки, которых нет в сторе, дописываются в конец в порядке `items`;
- размеры зажимаются в `minW/maxW/minH/maxH` и в `cols`;
- битый или не проходящий валидацию (valibot) стор молча падает на дефолты.

Без этого слияния устаревший стор либо рисует дырки, либо тихо съедает новые блоки.

Чтобы сбросить раскладку — вычисти ключ и перемонтируй компонент, либо перейди в контролируемый режим:

```tsx
const [layout, setLayout] = createSignal<DumbGridLayout | undefined>(undefined)
<DumbGrid layout={layout()} onLayout={setLayout} items={items} />
```

## Адаптивность

`cols` реактивен, поэтому breakpoint'ы — одна своя строчка:

```tsx
const cols = () => (width() < 700 ? 4 : width() < 1100 ? 6 : 12)
<DumbGrid cols={cols()} items={items} />
```

Размеры шире `cols` зажимаются, поэтому блок в 6 колонок на четырёхколоночной сетке станет во всю ширину, а не вылезет за край.

## Примитив `createDumbGrid`

Когда разметка должна быть твоя:

```tsx
import { createDumbGrid, packFlow, cellRect } from 'solid-dumb-kit'

const g = createDumbGrid({
  blocks: () => layout(),          // [{id, w, h, minW?, …, locked?}]
  cols: () => 12,
  rowHeight: () => 92,
  gapX: () => 12,
  gapY: () => 12,
  onReorder: (from, to) => setLayout(reorder(layout(), from, to)),
  onResize: (id, w, h) => setLayout(/* … */),
})

<div ref={g.container} style={{ display: 'grid', /* … */ }}>
  <For each={placed()}>
    {(p) => (
      <div ref={g.bind(p.id)} style={{ 'grid-column': `${p.col + 1} / span ${p.w}` /* … */ }}>
        …
        <div ref={g.resize(p.id)} />
      </div>
    )}
  </For>
</div>
```

`g.active()` — сигнал: `{ id, kind: 'move' | 'resize' }`, пока идёт жест, иначе `null`; удобно для подсветки.

Ref на контейнер **обязателен**: с него берутся ширина колонки и система координат. Блоки позиционируй явно (`grid-column-start`), а не авто-потоком — тогда размещение браузера не может разойтись с арифметикой.

## Движок без фреймворка

`createGridEngine` (в `gridCore.ts`) не импортирует `solid-js` вообще: принимает элементы, отдаёт функции отписки. `createDumbGrid` — тонкая обёртка, вешающая их на `onCleanup`. Математика живёт в `gridMath.ts` чистыми функциями:

| Функция | Что делает |
|---|---|
| `packFlow(items, cols, mode)` | порядок + размеры → `{col, row}` каждого блока (`flow` / `dense`) |
| `placeFree(items, cols)` | свои `{x, y}` → `{col, row}`, с клампом и разводом конфликтов |
| `pointToCell({x, y, w, m})` | пиксельный угол → ячейка сетки, с клампом |
| `overlaps({placed, id, col, row, w, h})` | занято ли место |
| `fitSpan({placed, id, col, row, want})` | обрезать желаемый размер по свободному месту |
| `cellRect(placed, metrics)` | единицы сетки → прямоугольник в px |
| `colWidth(contentW, cols, gapX)` | ширина колонки из ширины контейнера |
| `insertIndex({base, dragId, m, pointerX, pointerY})` | куда встанет перетаскиваемый |
| `moveDeltas({base, next, m, skipId})` | на сколько уезжает каждый сосед |
| `snapSpan({start, dx, dy, m, limits})` | дельта курсора → новый `{w, h}` |
| `resolveSpan(value, cols)` | `'half'` / `'5/12'` / `7` → колонки |
| `firstFreeCell({placed, cols, w, h})` | куда влезет новый блок |
| `rowCount(placed)` | сколько строк занято |

Все они покрыты тестами, которым не нужен DOM.
