# DumbGridDnd

Та же дашборд-сетка, но перетаскивание ведёт **нативный HTML5 drag-and-drop**.

```tsx
import { DumbGridDnd, createDumbGridDndGroup } from 'solid-dumb-kit'
```

Это **отдельный компонент**, а не режим [`DumbGrid`](DumbGrid.md). У них разные механики жеста и разные компромиссы; мешать их в одном коде — верный способ сломать обе. Общая у них только математика раскладки.

## Что выбрать

| | [`DumbGrid`](DumbGrid.md) | `DumbGridDnd` |
|---|---|---|
| Жест | наш, на указательных событиях | браузера, на `dragstart`/`dragover`/`drop` |
| Какая сетка под указателем | считаем сами по снятым прямоугольникам | решает браузер — `dragover` приходит на контейнер |
| Тач | работает | **не поддерживается** — HTML5 DnD там не существует |
| Картинка переноса | наша, живой клон в top layer | статичный снимок браузера |
| Автоскролл у краёв | наш | браузера |
| Выход за пределы страницы | нет | да — блок объявлен через `dataTransfer` |

Всё остальное совпадает, потому что это тот же код: арифметика раскладки, расступание соседей трансформом, пунктирная рамка места, снап ресайза, три режима, пресеты, персист, режим просмотра.

Ресайз в обоих — на указательных событиях: это не перенос, он не покидает свою сетку и требует покадровой точности, которой `dragover` не даёт.

## Использование

Такое же, как у `DumbGrid` — те же пропы, те же блоки:

```tsx
<DumbGridDnd
  cols={12}
  rowHeight={92}
  storageKey="dashboard"
  items={[
    { id: 'revenue', w: 'half', h: 2, content: () => <Revenue /> },
    { id: 'orders',  w: 'quarter',   content: () => <Kpi /> },
  ]}
/>
```

`mode` (`flow` / `dense` / `free`), `showGrid`, `editable`, `onRemove`, `layout`/`onLayout`, `spareRows`, пресеты размеров — всё как описано у [`DumbGrid`](DumbGrid.md).

## Перенос блока между сетками

```tsx
const group = createDumbGridDndGroup({
  onTransfer: (from, to) => { /* from: {grid, id, index} → to: {grid, index, x, y} */ },
})

<DumbGridDnd group={group} name="sales" items={salesItems()} />
<DumbGridDnd group={group} name="ops"   items={opsItems()} />
```

`accepts: (from) => boolean` у сетки отказывает приёму — проверяется дважды: в `dragover` (нет `preventDefault` → браузер дроп не даст) и ещё раз в `drop`, потому что правило приёма не должно жить в обработчике, который просто доставляет событие.

`group.over()` — сигнал с именем сетки под указателем, им удобно подсвечивать приёмник.

## Что уходит за пределы страницы

На `dragstart` блок кладётся в `dataTransfer`:

- `application/x-dumb-grid` — `{"grid": "...", "id": "..."}` (экспортируется как `DND_MIME`);
- `text/plain` — id, чтобы обычный текстовый приёмник получил что-то осмысленное.

Именно это делает блок понятным другому окну или чужому приёмнику. И это же причина, по которой Firefox вообще начинает перенос — без данных он отказывается.

## Движок без фреймворка

`createGridDndEngine` (`dndCore.ts`) не импортирует `solid-js`: принимает элементы, отдаёт функции отписки. `createDumbGridDndGroup` — тонкая Solid-обёртка. `dndSupported()` сообщает, есть ли API вообще.
