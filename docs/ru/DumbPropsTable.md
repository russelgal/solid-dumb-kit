# DumbPropsTable

Отладочная таблица: что на самом деле пришло в пропсах. Имя, тип, значение —
**всё**, включая функции и `undefined`.

```bash
pnpm add github:russelgal/solid-dumb-kit#path:/packages/props-table
```

```tsx
import { DumbPropsTable } from '@solid-dumb-kit/props-table'

<DumbPropsTable value={props} title="DumbTimeline" skip={['rows', 'spans']} />
```

Живьём — вкладка [`#props-table`](https://russelgal.github.io/solid-dumb-kit/#props-table).

## Зачем, если есть `JSON.stringify`

Привычный способ заглянуть в пропсы для этого не годится: `JSON.stringify`
**молча выбрасывает функции и `undefined`**. У компонентов кита почти всё
поведение и есть функции (`onOpen`, `dayClass`, `spanClass`), и в дампе их
просто нет — выглядит это как «проп не пришёл», хотя пришёл.

```tsx
const props = { onOpen: () => {}, summary: undefined, title: 'номер' }
JSON.stringify(props)   // {"title":"номер"} — и ищи, почему обработчик не зовётся
```

Таблица показывает обе строки: `ƒ onOpen(0)` и `undefined`. Разница между
«пропа нет» и «проп есть, значения нет» — обычно ровно то, чего не хватает.

## Как читается

- **Вложенные объекты идут первыми и разворачиваются** — в них чаще всего и
  кроется причина. Дальше функции, потом простые значения; внутри группы — по
  алфавиту, чтобы дамп не прыгал между перерисовками.
- **Массивы показываются первыми элементами и счётчиком** (`Array(2133)`): дамп
  двух тысяч броней никому не нужен. Сколько элементов раскрывать — `maxItems`.
- **Вид значения виден цветом**: объект, массив, функция, простое. Цвета вынесены
  в переменные `--dumb-props-object`, `--dumb-props-array`,
  `--dumb-props-function`, `--dumb-props-dim` — тёмная тема перекрашивает их
  своими.
- **Путь до значения** — в `title` ячейки: наведи на `stepMin`, увидишь
  `scale.stepMin`.

## Пропсы

| Проп | Тип | Что делает |
| --- | --- | --- |
| `value` | `object` | что разбираем: пропсы, стор, что угодно |
| `title` | `string` | заголовок над таблицей |
| `depth` | `number` | насколько глубоко разворачивать вложенное; `0` — не разворачивать, по умолчанию `1` |
| `maxItems` | `number` | сколько элементов массива показать, по умолчанию `8` |
| `skip` | `string[]` | что не разворачивать: `['rows', 'spans']` — там тысячи строк |
| `indent` | `number` | отступ на уровень вложенности, px (по умолчанию 14) |
| `headless` | `boolean` | не рисовать шапку — в узкой панели она только занимает строку |
| `class` | `string` | класс на обёртку |

Разметка голая — `table > thead/tbody`, без единого класса кита. Готовый
`table table-xs` из daisyUI ложится на неё без обёрток; это отладочный
инструмент, и оформление на нём должно быть потребителя.

## `dumpProps` — то же без разметки

Разбор живёт отдельно от таблицы: обычная функция без Solid и без DOM. Годится
в тесте, в логе и на сервере.

```tsx
import { dumpProps, describe } from '@solid-dumb-kit/props-table'

console.table(dumpProps(props, { depth: 2, skip: ['spans'] }))
describe(() => {})        // 'ƒ anonymous(0)'
describe([1, 2, 3])       // 'Array(3)'
```

`dumpProps` отдаёт плоский список: `key`, `path` (`scale.stepMin`), `depth`,
`type`, `kind` (`object` / `array` / `function` / `primitive`), `value`
(короткая запись) и `raw` — само значение, если вызывающему нужно больше.

## Чего он не делает

- **Не следит за изменениями.** Это снимок на момент рендера; таблица
  перерисуется, когда перерисуется её родитель.
- **Не годится для боевого кода.** Ключи читаются с объекта, а у Solid пропсы —
  перечислимые геттеры: чтение каждого свойства это подписка на реактивность.
  Для отладочной панели норма, в рабочем компоненте так делать нельзя.
- **Не защищает от тяжёлых значений**, кроме `maxItems` и `skip`: развернёшь
  массив на сто тысяч элементов — получишь сто тысяч строк.
