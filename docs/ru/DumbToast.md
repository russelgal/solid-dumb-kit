# DumbToast

Всплывающие сообщения: очередь, автоскрытие, вопрос с кнопками.

```tsx
import { DumbToaster, toast } from '@solid-dumb-kit/toast'
```

Шина живёт **в модуле**, а не в компоненте: звать `toast.error(...)` надо из
любого места — из адаптера хранилища, из обработчика ошибки, из кода, который про
разметку не знает вовсе. Компонент только рисует очередь.

## Четыре вещи, из-за которых это не десять строк

**Одинаковые схлопываются.** Двадцать файлов не залились — это одно сообщение со
счётчиком, а не двадцать плашек до потолка. Плашки с кнопками не схлопываются: у
каждой свой обработчик, и «×3» на вопросе означало бы, что два ответа потерялись.

**Таймер живёт снаружи.** Наведение мышью его останавливает: читать текст,
который уезжает из-под курсора, невозможно.

**Ошибка сама не гаснет.** Её читают и на неё реагируют, поэтому у `toast.error`
время жизни нулевое по умолчанию.

**Всплываем в top layer заново на каждое сообщение.** Top layer — стек, и кто
вошёл позже, тот выше. Тостер, висящий с самой загрузки, оказался бы НИЖЕ
модалки, открытой потом, — ровно там, где он не нужен: ошибки чаще всего и
прилетают из модалок.

## Вопрос вместо `confirm()`

```tsx
const ok = await toast.confirm('Удалить безвозвратно?', {
  yes: 'Удалить', danger: true, at: 'pointer',
})
```

У вопроса **нет таймера и нет крестика**: закрыть, не ответив, — это неявный
ответ, а какой именно, никто не знает. Отвечают кнопками.

`at: 'pointer'` ставит плашку **у курсора** — той же техникой, что контекстное
меню: невидимый якорь в точке и `anchor()`. Вопрос про конкретную строку удобнее
читать рядом с ней, а не в углу экрана.

Почему не `confirm()`: тот останавливает вкладку целиком — вместе с идущей
заливкой, — выглядит чужим в любой теме, и написать в нём, что именно случится,
нельзя.

## API

| | |
| --- | --- |
| `toast.info / success / error` | обычные сообщения |
| `toast.ask(text, actions)` | вопрос с произвольными кнопками |
| `toast.confirm(text, opts)` | `Promise<boolean>` |
| `toast.dismiss / clear` | закрыть одно / всё |
| `createToastBus()` | своя шина: тесты, две независимые области |

Кнопка: `{ label, run, kind: 'primary' | 'danger', keepOpen }`.
`DumbToaster` принимает `position`, `max`, свою `bus` и свою плашку через
`children`.

## Центр уведомлений

Погасшая плашка не пропадает, а улетает к краю — в панель истории, как в macOS.
Панель и её колокольчик со счётчиком непрочитанных живут в том же top layer
(Popover API), поэтому они над модалками без единого `z-index`.

```tsx
// оба ставятся ОДИН раз на приложение, обычно рядом с корнем
<DumbToaster position="bottom-right" max={6} />
<DumbToastCenter />
```

Колокольчик можно выключить (`bell={false}`) и открывать панель своей кнопкой —
`toast.toggleHistory()` зовётся откуда угодно, шина живёт в модуле.

| | |
| --- | --- |
| `toast.history()` | что уже прочитано и погашено |
| `toast.unread()` | счётчик непрочитанных |
| `toast.forget(id)` / `toast.clearHistory()` | убрать запись / очистить историю |
| `toast.toggleHistory()` | открыть или закрыть панель |
| `toast.pause() / resume()` | остановить таймеры (тостер делает это под курсором) |

`DumbToastCenter` принимает `side`, `bell`, `title`, `closeSide`, `animate` и
свою строку истории через `children`.

## Вопрос плашкой или вопрос окном

`toast.confirm` — для случая, когда работа продолжается: спросили про строку в
списке, ответили, пошли дальше. Если работа встала и ответ обязателен — закрыть
окно с несохранённым, стереть данные, — спрашивать надо модально, поверх того, о
чём спрашивают: `modal.confirm` из [`@solid-dumb-kit/modal`](DumbModal.md).
