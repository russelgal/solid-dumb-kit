# DumbUserManager

Экран администратора: выдать доступ, сменить роль, заблокировать, задать пароль,
выкинуть из сессий, удалить.

```tsx
import { DumbUserManager, suggestPassword, type UserRow } from '@solid-dumb-kit/user-manager'
```

## Кто за ним стоит — компонент не знает

Ни better-auth, ни своего эндпоинта, ни базы. Всё общение — через колбэки, и
каждый необязателен: не передали `onRemove` — кнопки «Удалить» просто нет. Один
и тот же экран годится администратору и тому, кому можно только посмотреть
список.

```tsx
<DumbUserManager
  users={users()}
  roles={[{ value: 'admin', label: 'Администратор', hint: 'всё' }]}
  currentUserId={me()?.id}
  onCreate={async (input) => { await api.createUser(input); await reload() }}
  onSetRole={async (id, role) => { await api.setRole(id, role); await reload() }}
/>
```

## Четыре решения, принятые за вас

1. **Пароль показывается один раз.** Заведение и смена пароля возвращают его
   плашкой — второй раз достать неоткуда, так и написано в тексте. Пустое поле
   пароля означает «сгенерируй сам» (`suggestPassword`).
2. **Владельца не трогаем.** `isOwner` гасит кнопки на клиенте — не как защиту
   (она на сервере), а чтобы не предлагать заведомо отказное действие.
3. **Себя не блокируем и не удаляем.** То же самое: сервер откажет, значит и
   кнопка неактивна, с подсказкой почему.
4. **Удаление в два клика, а не `confirm()`.** Браузерное окно блокирует всё,
   а вторая кнопка рядом со строкой понятнее и отменяется кликом мимо.

Ошибка от сервера показывается **как есть**: текст пишет тот, кто знает, что
именно не сошлось, а придуманное «Что-то пошло не так» помогает только тем, кто
и так догадался.

## Пропсы

| проп | тип | что делает |
| --- | --- | --- |
| `users` | `UserRow[]` | что показывать; сортировка и фильтр — на вашей стороне |
| `roles` | `RoleOption[]` | словарь ролей; пусто — роль показывается текстом |
| `currentUserId` | `string` | себе нельзя блокировку и удаление |
| `defaultRole` | `string` | роль по умолчанию в форме создания |
| `onCreate` | `(input) => Promise<void>` | не задан — формы «выдать доступ» нет |
| `onSetRole` | `(id, role) => Promise<void>` | не задан — роль показывается текстом |
| `onSetPassword` | `(id, password) => Promise<void>` | кнопка «Пароль» у строки |
| `onBan` | `(id, reason) => Promise<void>` | приостановить доступ |
| `onUnban` | `(id) => Promise<void>` | вернуть доступ |
| `onRevokeSessions` | `(id) => Promise<void>` | завершить все сессии |
| `onRemove` | `(id) => Promise<void>` | удалить, с подтверждением в строке |
| `formatDate` | `(iso: string) => string` | дата создания; по умолчанию как пришло |
| `title` | `string` | заголовок; пустая строка — без заголовка |
| `labels` | `UserManagerLabels` | все тексты; дефолты русские |
| `class` | `string` | классы на корень: отступы и ширину задаёт потребитель |

## Оформление

Стили — свои, инжектом, как у остальных пакетов кита: ни Tailwind, ни daisyUI не
требуется. Перекрашивается переменными на любом предке:

| переменная | по умолчанию | что красит |
| --- | --- | --- |
| `--dumb-um-fg` | `#0f172a` | основной текст |
| `--dumb-um-dim` | `#475569` | вторичный: почта, дата, заголовки колонок |
| `--dumb-um-bg` | `#fff` | фон карточек и таблицы |
| `--dumb-um-line` | `rgb(0 0 0 / .14)` | границы |
| `--dumb-um-primary` | `#1e293b` | кнопка действия |
| `--dumb-um-accent` | `#2563eb` | обводка фокуса |
| `--dumb-um-ok` | `#15803d` | активен, разблокировать, плашка успеха |
| `--dumb-um-bad` | `#b91c1c` | заблокирован, удалить, плашка ошибки |
| `--dumb-um-row-off` | `rgb(0 0 0 / .05)` | фон заблокированной строки |
| `--dumb-um-radius` | `10px` | скругления |

Заблокированная строка помечается **фоном, а не прозрачностью**: выцветший текст
в ките запрещён, а прочитать строку всё равно надо — за что и заблокировали.

Разметка держит честную структуру (`thead`/`tbody`, `button`, `label > input`),
поэтому свой daisyUI поверх ложится без обёрток — через `class` и селекторы по
`.dumb-um-*`.

## Пароли

`suggestPassword(length = 9)` отдаётся отдельно, без Solid: пригодится и в
скрипте наполнения базы, и в тесте. Из алфавита выкинуты пары, которые путают
на слух и на бумаге (`0/O/o`, `1/l/I`, `B/8`, `Z/2`) — пароль диктуют голосом и
переписывают с экрана. Заглавные оставлены: иначе он не пройдёт проверку «должна
быть заглавная». Байты берутся с отбраковкой, а не остатком от деления, чтобы
генератор не был смещён к началу алфавита.
