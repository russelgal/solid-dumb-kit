# Locator — alt-клик по элементу открывает его разметку в редакторе

Смотришь на страницу, видишь кнопку — жмёшь по ней с зажатым **Alt**, и
редактор открывается ровно на той строке, где эта кнопка написана. Ни поиска по
классам, ни «а в каком же это компоненте».

Пакет из двух половин, и обе нужны:

- **половина для сборщика** — плагин Vite `locator()` (`@solid-dumb-kit/locator/vite`):
  ставит каждому элементу разметки атрибут `data-loc="файл:строка:колонка"`;
- **браузерная половина** — `createLocator()` (`@solid-dumb-kit/locator`): ловит
  alt-клик, берёт атрибут у ближайшего предка и просит дев-сервер открыть это
  место.

Открывает файл **сам Vite**: у дев-сервера есть штатный эндпоинт
`/__open-in-editor` (`launch-editor`), и он же выбирает редактор — по
запущенному процессу либо по переменной `LAUNCH_EDITOR`. Своего эндпоинта пакет
не заводит.

Всё это живёт **только на дев-сервере**: у плагина `apply: 'serve'`, поэтому в
сборке нет ни атрибутов, ни браузерной половины.

```bash
pnpm add -D @solid-dumb-kit/locator
```

## Установка в проект

```ts
// vite.config.ts
import { locator } from '@solid-dumb-kit/locator/vite'

export default defineConfig({
  plugins: [
    // ⚠️ ПЕРЕД плагином фреймворка: тот сворачивает разметку в шаблоны, и
    // после него вставлять атрибут уже некуда.
    locator({ entry: 'src/App.tsx', editor: 'webstorm' }),
    solid(),
  ],
})
```

Названа точка входа — плагин сам вставит в неё браузерную половину, и приложение
о локаторе не узнает. Не названа — зовите `createLocator()` там, где удобно:

```ts
if (import.meta.env.DEV) createLocator()
```

## `locator(options)` — половина для сборщика

| проп | тип | по умолчанию | что делает |
| --- | --- | --- | --- |
| `attribute` | `string` | `'data-loc'` | имя атрибута с местом в исходнике |
| `entry` | `string` | — | путь от корня проекта, куда вставить браузерную половину; не задан — плагин в чужой код не лезет |
| `editor` | `string` | — | чем открывать, если `launch-editor` не угадал редактор по процессу (`webstorm`, `code`, `cursor`); значение из окружения не перебивается |
| `include` | `(id: string) => boolean` | свои `.tsx`, кроме тестов | какие файлы размечать |

Экспортируется и сама разметка — `markLocations(code, file, attribute?)`:
пригодится, если плагин вам не подходит и разметку надо позвать из своего.

## `createLocator(options)` — браузерная половина

| проп | тип | по умолчанию | что делает |
| --- | --- | --- | --- |
| `attribute` | `string` | `'data-loc'` | тот же атрибут, что у плагина |
| `endpoint` | `string` | `'/__open-in-editor'` | адрес, открывающий файл |
| `target` | `EventTarget` | `window` | где слушать клики |
| `key` | `'altKey' \| 'ctrlKey' \| 'metaKey' \| 'shiftKey'` | `'altKey'` | какая клавиша открывает редактор |

Возвращает функцию отписки. Solid не нужен: это движок без фреймворка, как и
остальные движки кита.

## Что надо знать

- **Компоненты не размечаются** — `<DumbTable/>` в DOM ничего не создаёт.
  Alt-клик попадает на ближайший элемент-предок, то есть на **место
  использования**: это обычно и есть то, что вы ищете.
- **Строки не сдвигаются.** Разметка строковая: парсер даёт позиции тегов,
  атрибут вставляется в ту же строку. Код не перегенерируется, поэтому и номера
  строк, и карты кода остаются верными.
- **Клик съедается целиком** (`preventDefault` + `stopPropagation` на
  перехвате): под курсором может оказаться «удалить», и открытие редактора — не
  повод это нажимать.
- **Цена** — около 3 мс на файл при первой трансформации, и только на
  дев-сервере. На проверенном проекте: 64 файла, 852 атрибута, 169 мс на весь
  `src`.
