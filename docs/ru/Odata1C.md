# Odata1C

Маленький клиент **стандартного интерфейса OData 1С** (`standard.odata`). Без привязки к фреймворку и изоморфный — нужны `fetch`, `TextEncoder` и `btoa`, поэтому работает и в браузере, и в Node 18+. Ни SolidJS, ни DOM.

```ts
import { createOdataClient, odataString, OdataError } from 'solid-dumb-kit'

const c = createOdataClient({ baseUrl: '/odata', login: 'Кладовщик', password: '…' })

const items = await c.list('Catalog_Номенклатура', {
  $select: 'Ref_Key,Description,Артикул',
  $filter: `substringof(${odataString('скотч')}, Description)`,
  $top: 20,
})
```

Ценность клиента не в десяти строчках `fetch` вокруг URL, а в наборе капризов 1С, зашитых в эти строчки. Каждый стоил кому-то потерянного вечера.

## Зачем это вместо голого `fetch`

| Каприз | Что будет без клиента |
| --- | --- |
| `$format=application/json;odata=nometadata` обязателен в **каждом** запросе | В ответе в каждом поле `odata.metadata` светится внутренний адрес сервера 1С. Заголовок `Accept` платформа игнорирует — параметр запроса единственный рычаг. |
| Пробелы кодируются как `%20`, но не `+` | `URLSearchParams` пишет `+`, и 1С **молча игнорирует** весь `$filter` — приезжает выборка без отбора и без единой ошибки. |
| Ошибки приходят объектом `odata.error`, иногда за BOM | `JSON.parse` спотыкается о BOM, а ответ 200 с `odata.error` внутри выглядит как успех. |
| `$filter`/`$orderby` могут быть запрещены правами роли | «Операция не разрешена в предложении "ГДЕ"» — 400 там, где ожидались строки. См. [`tailPage`](#tailpage--листание-набора-который-нельзя-сортировать). |
| Кириллица в логине | `btoa` падает на не-Latin-1, токен нужно собирать через UTF-8-байты. |

## Настройка

```ts
type OdataClientOptions = {
  baseUrl: string        // 'https://host/base/odata/standard.odata' либо путь прокси, например '/odata'
  login?: string         // Basic-авторизация…
  password?: string
  token?: string         // …либо готовый base64(логин:пароль)
  fetch?: typeof fetch   // свой fetch — логирование, ретраи, счётчики
  timeoutMs?: number     // по умолчанию 30000
}
```

**CORS.** Платформа 1С не отдаёт CORS-заголовки, поэтому напрямую с другого origin браузер до неё не достучится. Указывайте `baseUrl` относительным (`/odata`) и проксируйте dev-сервером или nginx — ради этого `baseUrl` и разрешён относительный.

**Креды.** `token` существует, чтобы не держать пароль под рукой: храните `base64(логин:пароль)` (Basic-авторизация — это ровно он) или, лучше, оставьте всё на сервере и выставьте наружу собственный эндпоинт.

## API

| Метод | Какой запрос уходит |
| --- | --- |
| `url(resource, params?)` | Только собирает URL — удобно для логов и тестов. |
| `request<T>(resource, params?, init?)` | Рабочая лошадка: любой метод, при желании JSON-тело. |
| `get<T>(resource, params?)` | `GET` сущности или набора, ответ как есть. |
| `list<T>(resource, params?)` | `GET` набора → массив `value` (`[]`, если его нет). |
| `one<T>(entity, refKey, select?)` | `GET Entity(guid'…')` — одна запись по ключу. |
| `count(resource, filter?)` | `$top=0&$inlinecount=allpages` → точное число строк. |
| `tailPage<T>(resource, opts)` | Страница с конца набора, свежие сверху. |

Всё падает с `OdataError` (`message` от 1С, `status` — когда HTTP-ответ был). `401` приводится к читаемому «Неверный логин или пароль 1С».

### `one` — чтение в обход запретов роли

`Entity(guid'…')` адресует запись по первичному ключу, а не через условие `ГДЕ`, поэтому продолжает работать в базах, где `$filter` роли запрещён. Когда имена нужны для пачки ключей, это превращается в запрос на ключ — кэшируйте и ограничивайте конкурентность.

### `tailPage` — листание набора, который нельзя сортировать

Хронологические наборы (документы, записи регистров) лежат от старых к новым, а `$orderby Date desc` — ровно то, что урезанная роль обычно отклоняет. `tailPage` обходится без сортировки вовсе: спрашивает общее количество, забирает последние `pageSize` строк через `$skip` и разворачивает их на клиенте.

```ts
const { rows, total } = await c.tailPage('Document_РеализацияТоваровУслуг', {
  page: 1,                       // 1 — самые свежие
  pageSize: 20,
  select: 'Ref_Key,Number,Date,Posted',
  filter: `substringof(${odataString(term)}, Number)`,   // уходит и в счёт, и в страницу
})
```

Стоит двух запросов на страницу (счёт + строки). Счёт — плата за невозможность отсортировать.

## Хелперы

| Функция | Зачем |
| --- | --- |
| `odataString(s)` | Оборачивает значение в апострофы и удваивает внутренние. Пользовательский ввод — всегда через неё. |
| `toBase64(s)` | base64 по UTF-8 — то, благодаря чему работают кириллические логины. |

Литералы, на которых 1С настаивает: даты — `datetime'2026-04-01T00:00:00'`, ссылки — `guid'…'`, регистратор записи регистра — `cast(guid'…', 'Document_…')`.

## Грабли

- **Длина URL.** nginx перед 1С отвечает `414` примерно с 8000 символов, а кириллица в именах сущностей после кодирования занимает по шесть символов на букву. Фильтр из ~30 ключей через `or` уже подбирается к границе — режьте длинные списки ключей пачками по ~25 и склеивайте результаты.
- **Один список дешевле тысячи точечных чтений.** Целый справочник (десятки тысяч строк, `Ref_Key` плюс пара полей) обычно приезжает одним запросом примерно за секунду. Нужны имена для сотен ключей — выкачайте словарь один раз и закэшируйте.
- **`$select` — не оптимизация, а необходимость.** Без него регистр отдаёт все свои ресурсы разом, и ответ раздувается.
- **Запись.** `POST` возвращает `201` с созданным объектом, `PATCH` — `200`, `DELETE` — `204` (пустое тело, клиент вернёт `undefined`). Проведение документа — `POST` на `Document_…(guid'…')/Post()`. Закрытые периоды 1С защищает сама.
