# MCP-сервер кита

Отдаёт агенту то, что нужно знать о `solid-dumb-kit`, не вычитывая репозиторий
целиком: какие пакеты есть, какие у компонента пропсы, как выглядит рабочий
пример, что написано в доках и чего в этой репе делать нельзя.

Зависимостей нет ни одной — сервер запускается там, где `node_modules` кита
может не быть вовсе. Нужен только Node 18+.

## Инструменты

| Инструмент | Что отдаёт |
| --- | --- |
| `list_packages` | все пакеты: имя, версия, за что отвечает |
| `package_api` | барр-файл пакета целиком — в ките он с комментариями к каждому экспорту |
| `component_props` | тип пропсов компонента вместе с JSDoc над каждым полем |
| `example` | список примеров или исходник одного; примеры держит в актуальном виде тест |
| `docs` | страница документации, английская или русская |
| `rules` | железные правила репы: никакого reflow, импорты под Solid 2, контраст |
| `search` | поиск по исходникам, примерам и докам |

## Подключение

К проекту, который **потребляет** кит (агент будет знать API кита при работе
над чужим кодом) — в `.mcp.json` рядом с его `package.json`:

```json
{
  "mcpServers": {
    "solid-dumb-kit": {
      "command": "node",
      "args": ["/абсолютный/путь/к/solid-dumb-kit/mcp/server.mjs"]
    }
  }
}
```

Либо одной командой:

```bash
claude mcp add solid-dumb-kit -- node /абсолютный/путь/к/solid-dumb-kit/mcp/server.mjs
```

Путь абсолютный намеренно: корень репы сервер вычисляет от собственного
расположения, поэтому рабочая директория запуска роли не играет.

## На другом компьютере

Знания сервера — это сами файлы репы (`packages/*/src`, `docs`, `examples`,
`CLAUDE.md`), поэтому «поставить один пакет из npm» тут не работает: рядом
должна лежать копия репозитория. Зато зависимостей у сервера нет, значит
ставить после клона нечего — `npm install` не нужен вовсе:

```bash
git clone --depth 1 git@github.com:russelgal/solid-dumb-kit.git ~/.solid-dumb-kit
claude mcp add solid-dumb-kit -- node ~/.solid-dumb-kit/mcp/server.mjs
```

Клон занимает около 6 МБ (в репе лежит собранный `dist` — он нужен
потребителям, которые ставят пакеты прямо с GitHub). Обновляется
`git -C ~/.solid-dumb-kit pull`.

> **Почему не `npx github:russelgal/solid-dumb-kit`.** Пробовал — не работает,
> и дело не в MCP. При установке из git npm ставит и dev-зависимости, а в корне
> репы их два десятка вида `workspace:*` — этот протокол понимает pnpm, но не
> npm, и установка падает с `EUNSUPPORTEDPROTOCOL`. Чинится это только отказом
> от `workspace:*` в корне, то есть поломкой рабочей схемы ради одной команды.

Если кит на этой машине и так правится — указывай путь к своей рабочей копии,
а не к отдельному клону: тогда сервер отвечает с невыпущенными правками и по
той ветке, на которой ты сейчас.

## На хостинге: подключение одним адресом

Тот же сервер отвечает и по HTTP — тогда ни клона, ни Node на машине не нужно
вовсе:

```bash
claude mcp add --transport http solid-dumb-kit https://solid-dumb-kit.vercel.app/mcp
```

Витрина компонентов живёт на том же домене (`/`), сервер — на `/mcp`, а
страница-визитка с этой командой — на `/mcp-info`.

Данные там — снимок репы (`mcp/snapshot.json`), собираемый на деплое: диска с
репозиторием на хостинге нет. Снимок пересобирается на каждый пуш в `main`,
поэтому ответы догоняют репу сами. Невыпущенных правок он, разумеется, не
видит — для работы над самим китом запускай stdio-версию по рабочей копии.

### Деплой на Vercel

```bash
npx vercel            # первый раз: логин и вопросы о проекте
npx vercel --prod
```

На вопросе про фреймворк выбирай **Other**: сборка описана в `vercel.json`
(`buildCommand: node mcp/snapshot.mjs`, установка зависимостей отключена — их
нет). Дальше свяжи проект с репозиторием на GitHub, и снимок будет
пересобираться сам на каждый пуш.

Эндпоинт открытый: кит и так публичен, скрывать нечего. Появится приватное —
закрывать проверкой заголовка в `api/mcp.mjs`, отдельной сборки для этого не
надо.

### Что внутри

| Файл | Зачем |
| --- | --- |
| `mcp/tools.mjs` | сами инструменты — общие для stdio и HTTP |
| `mcp/sources.mjs` | откуда брать знания: файлы репы или снимок |
| `mcp/server.mjs` | транспорт stdio |
| `api/mcp.mjs` | транспорт HTTP (Vercel-функция) |
| `mcp/snapshot.mjs` | сборка снимка |

Транспорт HTTP нарочно простейший: POST с одним сообщением JSON-RPC — один JSON
в ответ. Ни сессий, ни SSE: на serverless каждый запрос попадает в свой инстанс,
и держать между ними состояние всё равно нечем, а инструменты его и не требуют.

## Проверка

```bash
printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' \
  | node mcp/server.mjs
```

В ответ придут две строки JSON: приветствие сервера и список инструментов.
Служебные сообщения сервер пишет в `stderr` — `stdout` занят протоколом.
