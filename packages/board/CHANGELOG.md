# @solid-dumb-kit/board

## 0.2.0

### Minor Changes

- 78a7bdd: Блоки доски живут на сетке ячеек, широкий блок втискивается в остаток строки

  **Ломающая правка.** Высота блока задаётся пропом `blockRows` (строки зоны), а
  не содержимым: блок занимает свои ячейки целиком, и пиксельную высоту в разметке
  задавать больше не надо.

  ```diff
  -<article style={{ height: `${h * 76 + (h - 1) * 8}px` }}>
  +// высота приходит из сетки
  +<DumbBoard blockRows={(w) => w.h} …>
  ```

  Место блока задаётся явными `grid-column`/`grid-row`, посчитанными `packFlow`, а
  не CSS `order`. Раз размеры целые, позиции — чистая арифметика: снимок размеров
  блоков не нужен вовсе, `IntersectionObserver` наблюдает только углы зон и высоты
  секций, а ширину колонки и отступы даёт `ResizeObserver`.

  Новый проп `blockLimits` — пределы размера блока в ячейках
  (`{ minW, maxW, minH, maxH }`). `minW` служит дважды: это порог ресайза и ширина,
  до которой блок согласен ужаться, чтобы влезть в остаток строки вместо переезда
  вниз. Ужатая ширина **нигде не хранится**: она выводится из раскладки, поэтому на
  просторном месте блок сам разворачивается обратно, а данные остаются нетронутыми.

  **Ресайз блоков.** Ручка-уголок появляется, только если задан `onBlockResize` —
  размер живёт в данных потребителя, и доска не меняет его сама. Пока тянут,
  двигается рамка-превью: применять каждый снап покадрово значит перекладывать всю
  зону и запускать пачку анимаций. Жест указательный, поэтому работает и пальцем,
  в отличие от переноса.

  Добавлены `showGrid` (разметка сетки внутри секций: `true` / `'drag'` / `false`),
  `zoneGap` и `labels.resizeBlock`. Ширины в `blockSpan`/`blockLimits` принимают
  доли (`'half'`, `'2/5'`) — те же, что у `DumbGrid`.

  Исправлено: подложка разметки рисовалась от padding-box зоны, а сетка начинается
  после padding — линии съезжали. Теперь у слоя `padding: inherit` и
  `background-origin: content-box`, как в `DumbGrid`.

  Из пакета убраны `slotAt`, `rowsFor` и типы `ZoneGeom`/`ZoneFlow`: их заменила
  математика сетки.

  В `@solid-dumb-kit/grid`: `packFlow` понимает `minW` у блока (без него поведение
  прежнее), `gridLinesBackground` принимает толщину линии и экспортируется наружу —
  доска рисует разметку теми же линиями. Цвет линий берётся из `--dumb-grid-line`
  (фолбэк — нейтральный серый), чтобы тема потребителя могла его перебить.

- a34c809: Секции хранят свои блоки, размер блока — в ячейках сетки

  **Ломающая правка.** Было два массива — секции отдельно, блоки отдельно, плюс
  функция «в какой секции блок». Стало один: `sections[i].items`. Пропы `items` и
  `section` убраны, добавлен `setSections` — доска собирает новую раскладку сама и
  отдаёт её на каждом шаге жеста, как `DumbSortableDnd` отдаёт `setItems`.
  `onMove`/`onSectionMove`/`onSectionResize` остались уведомлениями.

  ```diff
  -<DumbBoard sections={sections()} items={widgets()} section={(w) => where()[w.id]} …>
  +<DumbBoard sections={sections()} setSections={setSections} …>
  ```

  Блоки теперь бывают разной ширины (`blockSpan` — колонки зоны) и высоты —
  подробности размеров в правке про сетку ячеек.

  Заодно исправлено: замер после дропа снимался, пока блоки ещё доигрывали FLIP, а
  `boundingClientRect` учитывает transform — начало координат зоны уезжало, и
  следующий жест стартовал блоки не оттуда, где они на самом деле.

### Patch Changes

- 815e20f: Доска уважает `[data-no-drag]`

  Кнопка внутри блока не работала: нажатие уезжало в перетаскивание, и клика не
  случалось. Теперь жест с помеченного элемента не стартует — признак тот же, что
  у `DumbGrid`, чтобы не помнить два разных.

  Нужно для своих контролов на блоке: удаление, меню, поле ввода.

- 0e1c596: Блоки разного размера больше не качаются при медленном перетаскивании

  Тащишь узкий блок на широкий — место менялось, и широкий вставал ровно под
  курсор; следующее событие меняло их обратно, и так весь жест. Замерено: шесть
  перестановок за один медленный проход.

  Три правила разом: порог по середине цели в сторону движения (SortableJS),
  один обмен на один заход на соседа, и запрет вернуть блок туда, откуда он
  только что уехал. Последний держится, только пока рука едет в ту же сторону, —
  на развороте снимается, иначе нельзя передумать посреди жеста.

  Проверено перебором двенадцати пар блоков разного размера: качели нет ни в
  одной, было в семи.

- 59b986f: `createStableOrder` — порядок разметки по появлению, а не по id

  Разметка у `DumbSortableDnd` и `DumbBoard` должна стоять неподвижно, чтобы
  перестановка не двигала узлы. Держалось это сортировкой по id — стабильно, но
  читать разметку невозможно: `r10` встаёт раньше `r2`. Теперь порядок задаётся
  тем, кого увидели первым, и на старте совпадает с порядком `items`.

  Помощнику нужно отдавать ВЕСЬ список: по подмножеству его уборка выбросит тех,
  кого в нём не было. Для подмножеств есть `rank`.

## 0.1.3

### Patch Changes

- Починена сортировка блоков внутри секции: при движении вперёд блок улетал в
  конец списка. Курсор проваливался в **зазор сетки** между соседями, промах по
  блокам принимался за «пустое место» и означал «в конец».

  Теперь «мимо блоков» толкуется как «в конец» только для блока, приехавшего из
  ЧУЖОЙ секции — там пустое место единственное, на что можно навести. Внутри своей
  секции хвост не нужен: чтобы встать последним, наводишь на последний блок.

## 0.1.2

### Patch Changes

- Структурные стили доски кладутся в `<head>` и переживают размонтирование. Раньше
  `<style>` жил внутри дерева компонента, а флаг «уже вставили» — в модуле: ушёл со
  страницы первый экземпляр, фреймворк убрал разметку вместе со стилями, флаг
  остался поднятым, и на возврате доска рисовалась без стилей — секции в одну
  колонку, ручки не на месте.

  В `@solid-dumb-kit/shared` появился `injectStyle(id, css)` — тем же граблям
  подвержен любой компонент, который решит инжектить стили из разметки.

## 0.1.1

### Patch Changes

- Порядок РЕНДЕРА отвязан от порядка показа — и у секций, и у блоков. Без этого
  обещание «внутри секции DOM не трогается» было неправдой: `<For>` шёл по
  показному порядку, и каждая перестановка двигала узлы. Теперь `<For>` идёт по
  устойчивой сортировке (по id), а порядок на экране задаёт CSS `order`, как и
  задумано. Мутаций DOM за жест стало ноль — включая перестановку секций.

  Место блока в секции считается одной картой на всю доску, а не поиском по
  массиву на каждый блок: двести блоков — это были сорок тысяч сравнений на
  перерисовку.

## 0.1.0

### Первый выпуск

`DumbBoard` — доска секций с блоками. Блоки переставляются внутри секции и
переносятся между секциями, сами секции переставляются за заголовок и меняют
размер за край или угол; двойной клик по шапке разворачивает во всю ширину и
обратно.

Выросло из пробы `examples/lab/OrderBoard`, но с нормальным состоянием: у пробы
оно было размазано по пяти `Record`-ам, а компоненту хватает двух массивов —
порядок в `items` и есть порядок блоков, размер живёт на самой секции.
