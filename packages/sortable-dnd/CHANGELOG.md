# @solid-dumb-kit/sortable-dnd

## 0.8.0

### Minor Changes

- ffecd9a: Порядок задаётся только CSS `order` — DOM за жест не меняется вовсе

  Элементы рендерятся в неизменном порядке (по id), а показывает их браузер по
  `order`; раньше `<For>` шёл по порядку показа и при каждой перестановке двигал
  узлы. Замеры мест снимаются на монтировании и на `ResizeObserver`, а не на
  каждом старте жеста. Отмена по Escape ловится через `keyup` (`keydown` во время
  нативного драга до страницы не доходит), поэтому итог подводится через 24 мс
  после `dragend`.

  Требование к потребителю: контейнер должен быть flex или grid — иначе `order`
  не действует. Класс на контейнере задаёт потребитель, проверить это кит не может.

### Patch Changes

- 3ff9031: Перестановка считается по затронутому отрезку, а не по всему списку

  `commit` обходил все элементы, на каждом звал `slotAt` (сумма высот с начала
  списка, O(k)) и `indexOf` — то есть O(n²) на каждый `dragover`. Двигаются же
  только места между `from` и `to`: обычно две-три строки.

  Базовая вершина в разности сокращается, поэтому проход по началу списка не
  нужен вовсе. В режиме сетки вдобавок не строится копия порядка.

  Замер на 300 строках, жест через десяток мест: 17 → 10 мс скриптового времени.

- 59b986f: `createStableOrder` — порядок разметки по появлению, а не по id

  Разметка у `DumbSortableDnd` и `DumbBoard` должна стоять неподвижно, чтобы
  перестановка не двигала узлы. Держалось это сортировкой по id — стабильно, но
  читать разметку невозможно: `r10` встаёт раньше `r2`. Теперь порядок задаётся
  тем, кого увидели первым, и на старте совпадает с порядком `items`.

  Помощнику нужно отдавать ВЕСЬ список: по подмножеству его уборка выбросит тех,
  кого в нём не было. Для подмножеств есть `rank`.

## 0.7.0

### Minor Changes

- `DumbSortableDnd` переустроен по образцу `DumbBoard`: порядок меняется СРАЗУ, на
  каждом шаге жеста, а не копится внутри до отпускания.

  Копить было ошибкой. Коммит тогда висит на `drop`, а браузер доставляет его не
  всегда — при быстром движении Chrome глотает `dragover`, и без свежего дроп не
  считается состоявшимся. Отсюда «сортировка сломалась»: соседи расступались, а на
  отпускании всё откатывалось. Теперь терять нечего, и вся машинерия вокруг
  `drop`/`dropEffect`/`dragleave` из движка ушла — он стал на 90 строк короче.

  `setItems` теперь зовётся по ходу жеста, поэтому данные всё время совпадают с
  экраном. Escape возвращает элемент на исходное место. Добавлен необязательный
  `onEnd(from, to)` — один вызов в конце жеста, удобно для сохранения.

## 0.6.1

### Patch Changes

- Починена сортировка, которая молча откатывалась. Коммит висел на событии `drop`,
  а браузер доставляет его не всегда: при быстром движении Chrome глотает
  `dragover`, и без свежего дроп не считается состоявшимся. Особенно заметно было
  при автопрокрутке — там курсор стоит на месте, и событий почти нет. Соседи всё
  время расступались, отпускаешь — и порядок прежний.

  Теперь итог подводит `dragend`, который приходит всегда, а «состоялся ли жест»
  решается своим признаком: отпустили над зоной и не нажимали Escape. По
  `dropEffect` это не различить — у несостоявшегося дропа он `none`, ровно как у
  отменённого жеста.

## 0.6.0

### Minor Changes

- Убран `@atlaskit/pragmatic-drag-and-drop` — оба движка теперь на голых событиях
  браузера. Платили за него зря: хиттест всё равно делает браузер, а из его услуг
  оставалась нормализация `dragenter`/`dragleave` да «honey pot» под чужой баг с
  залипшим `:hover`. За это — 6.9 КБ gzip и CJS-хвост `bind-event-listener`,
  который у потребителя дважды ронял дев («does not provide an export named
  'bind'»).

  Слушателей теперь четыре на контейнер, а не по четыре на элемент: события
  всплывают, и `ev.target.closest` скажет, кто под курсором. На трёхстах строках
  это 4 записи в таблице слушателей вместо 1200.

  Зависимостей у обоих пакетов больше нет вовсе. Из `optimizeDeps.include` у
  потребителя записи про `pragmatic` и `bind-event-listener` можно убрать.

## 0.5.0

### Minor Changes

- 9ee1f5f: Кит разъехался на пакеты — по одному на компонент, у каждого своя версия и свои
  зависимости. Ставится только то, что нужно: `@solid-dumb-kit/table` больше не
  тянет за собой `@atlaskit/pragmatic-drag-and-drop`, а `@solid-dumb-kit/sortable`
  не тянет вообще ничего.

  Ломающее: единого пакета `solid-dumb-kit` больше нет, импорты меняются на
  конкретные пакеты (`import { DumbTable } from '@solid-dumb-kit/table'`).
  `@solid-dumb-kit/shared` теперь выкладывает наружу всё содержимое — `shouldAnimate`,
  `measure`, `scrollParent`, `createPressGate` и прочее: пакеты стоят на нём и
  подглядывать в чужие файлы больше не могут.
